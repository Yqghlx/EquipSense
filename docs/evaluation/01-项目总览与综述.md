## 一、项目概况

EquipSense（内部代号 EquipAI）是一个端到端的**工业设备智能监控与预测维护 SaaS 平台**。核心能力闭环：

```
实时监控 → 智能告警(三级) → AI 根因分析(四级降级) → 自动工单(九状态) → 知识沉淀(双表审核)
```

## 三、架构核心优势

### 3.1 事件驱动解耦

后端模块间通过 `IEventBus` → `IEventHandler` 完全解耦：

```
Telemetry → TelemetryReceivedEvent → 告警评估
  → AlertTriggeredEvent → SignalR 推送 + AI 根因分析 + 自动建单
    → AnalysisCompletedEvent → 工单关联分析结果
      → WorkOrderCreatedEvent → 通知推送
      → WorkOrderStatusChangedEvent → 知识沉淀 + 外部集成 + 通知
```

7 个领域事件串联起「设备 → 告警 → 分析 → 工单 → 知识库」全链路，模块间零直接调用。

### 3.2 三层多租户隔离

```
Layer 1 (数据层): EF Core 全局查询过滤器 — 自动注入 WHERE tenant_id = @current
Layer 2 (中间件层): TenantResolutionMiddleware — JWT claim + X-Tenant-Id 双重限定
Layer 3 (通信层): SignalR Group — 连接时自动加入 tenant:{id} 组
```

### 3.3 AI 四级自动降级

```
L4 (ML.NET SrCnn) → L2 (规则引擎) → L3 (统计分析) → L1 (LLM)
 样本充足+异常    知识库匹配成功   基线+数据质量达标   兜底方案
  置信度 0.85+     置信度 0.5-0.9   置信度 0.4-0.8    置信度 0.3-0.7
```

数据质量评分联动置信度，LLM 不可用时自动降级通用经验诊断（置信度 0.3）。

### 3.4 告警防风暴

30 分钟窗口内，同设备同指标同规则：
- **第 1 次**：立即创建新告警 + 推送通知
- **第 2-3 次**：更新已有告警（聚合计数）
- **超过 3 次**：静默（不重复通知）

重启后窗口重置但有 DB 兜底防重复告警。

### 3.5 知识沉淀安全边界

```
AI 生成规则 → PendingRule (待审核) → 专家批准 → KnowledgeRule (正式使用)
                                     → 专家驳回 → 记录日志
```

高置信度(≥0.8)且维修时长达标的工单关闭后自动触发 LLM 规则生成。

## 四、主要风险

| 优先级 | 风险 | 影响 | 建议 | 对应报告 |
|--------|------|------|------|---------|
| P0 | 单点开发者 (Bus Factor = 1) | 知识完全依赖一人 | 代码审查 + 知识分享 + 备选维护者 | 05-代码质量 |
| P0 | 单点开发者 (Bus Factor = 1) | 故障响应依赖个人 | 代码审查 + 知识分享 + 备选维护者 | 05-代码质量 |
| P1 | 正式生产存储/异地恢复尚未完成演练 | 代码级备份恢复证据不能证明目标部署形态的灾难恢复能力 | 在生产等价数据库、附件存储、密钥和 Redis 条件下完成定期恢复演练并记录 RTO/RPO | 07-运维 |
| P1 | MFA 恢复码尚未现场演练 | 恢复码保存不当或未验证可用性会延长高权限账户恢复时间 | 验证恢复码单次消费、重新生成、审计和失效流程 | 06-安全纵深 |
| P1 | 读副本和容量基线未经过真实负载 | 大租户可能影响小租户 | k6 写路径/多租户压测 + 慢查询基线 | 11-性能 |
