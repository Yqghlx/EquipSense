## 三、架构核心优势

### 3.1 事件驱动解耦

后端模块间通过 `IEventBus` → `IEventHandler` 完全解耦：

```
Telemetry → AlertTriggeredEvent → 告警评估
  └→ AnalysisCompletedEvent → 工单关联分析
     └→ WorkOrderStatusChangedEvent → 知识沉淀 + 外部集成 + 通知
```

5 个领域事件 (`TelemetryReceivedEvent`, `AlertTriggeredEvent`, `AnalysisCompletedEvent`, `WorkOrderCreatedEvent`, `WorkOrderStatusChangedEvent`) 串联起设备、告警、分析、工单、知识库全链路。

### 3.2 三层多租户隔离

```
Layer 1: EF Core 全局查询过滤器 — 自动注入 WHERE tenant_id = @current
Layer 2: TenantResolutionMiddleware — JWT tenant_id + X-Tenant-Id 双重限定
Layer 3: SignalR Group 隔离 — 连接时加入 tenant:{id} 组
```

### 3.3 AI 四级降级管线

```
L4 ML.NET SrCnn (异常检测) → L2 规则引擎 (知识库匹配) → L3 统计分析 (Z-Score) → L1 LLM 诊断 (兜底)
```

数据质量评分联动置信度，LLM 不可用时自动降级通用经验诊断。

### 3.4 告警防风暴

30 分钟窗口内，同设备同指标同规则：
- 第 1 次：立即告警
- 第 2-3 次：更新已有告警
- 超过 3 次：静默

## 四、主要风险

| # | 风险 | 影响 | 建议 |
|---|------|------|------|
| 1 | 单点开发者 (Bus Factor = 1) | 知识依赖一人 | 代码审查 + 知识分享 + 备选维护者 |
| 2 | InMemoryEventBus 不持久 | 重启丢失事件 | Phase 3 迁移 RabbitMQ |
| 3 | 后台服务无分布式锁 | 多实例重复执行 | RedLock / Leader Election |
| 4 | tmux 日志 631MB | 可能含敏感信息 | 清理并 gitignore |
