# EquipSense 开发者快速上手指南

> 按"任务"组织的实操指南，面向新加入项目的开发者

## 一、准备工作

### 1.1 仓库

```bash
git clone <repo-url>
cd EquipSense
```

### 1.2 环境要求

| 工具 | 版本 | 用途 |
|------|------|------|
| .NET SDK | 8.0.x | 后端编译 |
| Node.js | 20+ | 前端构建 |
| Docker | 24+ | 基础设施 |
| Docker Compose | v2+ | 服务编排 |

### 1.3 启动基础设施

```bash
docker compose -f docker/docker-compose.dev.yml up -d
# 启动 PostgreSQL:5432, Redis:6379, Mosquitto:1883
```

### 1.4 启动后端

```bash
cd src
dotnet run --project EquipAI.WebAPI
# 监听 http://localhost:8080
# 首次启动自动迁移 + 种子数据
# Swagger: http://localhost:8080/swagger
```

### 1.5 启动前端

```bash
cd frontend
npm install   # 首次
npm run dev   # 监听 http://localhost:5173
```

### 1.6 模拟遥测数据

```bash
dotnet run --project tools/EquipAI.Simulator -- \
  --tenant 11111111-1111-1111-1111-111111111111 \
  --devices 3 --interval 5 --anomaly-rate 5
```

### 1.7 登录

开发/测试管理员凭据由测试环境注入；生产环境管理员初始密码来自 `SEED_ADMIN_PASSWORD`，首次登录后必须修改。

## 三、典型开发场景

### 场景 A: 给我的新功能加一个 API 端点

**步骤**:

```
1. 定义 DTO (如果请求/响应是新的)
   → 后端: src/EquipAI.Application/{Module}/DTOs/
   → 前端: frontend/src/types/index.ts

2. 添加业务方法
   → src/EquipAI.Application/Services/{Module}Service.cs
   → 注入 IServiceScopeFactory + IEventBus (如需事件)
   → 注意: 所有 DB 查询用 IgnoreQueryFilters + 显式 TenantId

3. 注册 DI
   → src/EquipAI.WebAPI/Extensions/ServiceCollectionExtensions.cs

4. 添加 Controller 端点
   → src/EquipAI.WebAPI/Controllers/{Module}Controller.cs
   → 标记 [Authorize] + [RequirePermission("resource:action")]
   → 统一返回 PagedResult<T> 或 {Entity}Dto

5. 添加前端 hook
   → frontend/src/hooks/use{Module}.ts
   → useQuery / useMutation + invalidateQueries

6. 添加页面或更新已有页面
   → frontend/src/pages/

7. 添加翻译
   → frontend/src/i18n/zh.json + en.json

8. 添加测试
   → tests/EquipAI.Tests.Unit/ + frontend/src/hooks/__tests__/
```

**Checklist**:
```
[ ] DTO 对称性检查 (导入✔ 导出✔)
[ ] 枚举序列化为字符串 (非数字)
[ ] 分页参数 page/pageSize
[ ] [Authorize] + [RequirePermission]
[ ] 审计日志 (AuditActionFilter 自动)
[ ] TanStack Query onSuccess invalidate
[ ] i18n 中英文 key
[ ] 至少 1 个单元测试
```

### 场景 C: 排查 SignalR 重连问题

**常见问题与诊断**:

| 症状 | 可能原因 | 检查点 |
|------|---------|--------|
| 连接断开后不重连 | 无网络 / Hub 未启动 | 浏览器 DevTools → Network → WS → 检查 101 |
| 重连后事件重复 | handler 在 onreconnected 重新注册 | 检查 useSignalR 是否只调用一次 registerHandlers |
| 某类事件不触发 | handler 未注册 / 后端未推送 | 后端日志搜 `SendAsync` |
| 跨租户串数据 | SignalR Group 错误 | 检查 `tenant:{tenantId}` 拼写 |
| 前端不断刷新 | invalidateQueries 太频繁 | 检查 useSignalR 中 invalidate 的 queryKey |

**日志关键字**:
```
后端: "SignalR 推送失败", "SendAsync", "OnAlertTriggered"
前端: signalr.ts → connection.onreconnecting / onreconnected
指标: equipai_signalr_connections{tenant_id="..."}
```

### 场景 D: 做数据库迁移

**手动执行**:

```bash
cd src/EquipAI.Infrastructure
dotnet ef migrations add MyMigration --startup-project ../EquipAI.WebAPI
dotnet ef database update --startup-project ../EquipAI.WebAPI
```

**注意事项**:
```
1. 迁移命名规范: {yyyyMMddHHmmss}_描述性名称
2. 检查生成的 Up/Down 方法是否正确
3. 确保 Down 方法能完整回滚
4. 已上生产后: 先验证迁移脚本再执行
5. 表名/列名用 snake_case (统一风格)
```

**配置类模板**:
```csharp
public class MyEntityConfiguration : IEntityTypeConfiguration<MyEntity>
{
    public void Configure(EntityTypeBuilder<MyEntity> builder)
    {
        builder.ToTable("my_entities");
        builder.HasKey(e => e.Id);
        builder.Property(e => e.Id).HasColumnName("id");
        builder.Property(e => e.TenantId).HasColumnName("tenant_id");
        builder.Property(e => e.Name).HasColumnName("name").HasMaxLength(200);
        builder.HasIndex(e => new { e.TenantId, e.Name });
    }
}
```

### 场景 E: 添加一个新的 BackgroundService

**模板**:

```csharp
public class MyPeriodicService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly ILogger<MyPeriodicService> _logger;

    public MyPeriodicService(IServiceScopeFactory scopeFactory, ILogger<MyPeriodicService> logger)
    {
        _scopeFactory = scopeFactory;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        _logger.LogInformation("MyPeriodicService 已启动");

        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await DoWorkAsync(stoppingToken);
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
            {
                break;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "MyPeriodicService 执行失败");
            }

            await Task.Delay(TimeSpan.FromMinutes(5), stoppingToken);
        }
    }

    private async Task DoWorkAsync(CancellationToken ct)
    {
        using var scope = _scopeFactory.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();

        // ⚠️ 后台服务必须 IgnoreQueryFilters + 显式 TenantId
        var items = await db.SomeEntities
            .IgnoreQueryFilters()
            .Where(e => e.TenantId == someTenantId)
            .ToListAsync(ct);
    }
}
```

**注册**:
```csharp
// ServiceCollectionExtensions.cs
services.AddHostedService<MyPeriodicService>();
```

### 场景 F: 调试多租户问题

**常见问题**:

| 症状 | 原因 | 修复 |
|------|------|------|
| HTTP 请求查不到数据 | 全局过滤器正常工作 | ✅ 正常行为 |
| 后台服务查不到数据 | ITenantContext=Guid.Empty | 加 IgnoreQueryFilters |
| 跨租户看到对方数据 | 缺少显式 TenantId 过滤 | 加 .Where(e.TenantId == ...) |
| Admin 切租户无效 | X-Tenant-Id 被错误忽略 | 检查角色是否为 SystemAdmin |

**调试技巧**:
```sql
-- 查看当前 EF Core 生成的 SQL (启用日志)
SET app.tenant_id = 'your-tenant-id';
SELECT * FROM devices WHERE tenant_id = current_setting('app.tenant_id')::uuid;

-- 验证租户过滤器
SELECT * FROM devices; -- 看是否有 WHERE tenant_id 自动注入
```

## 六、常见问题 (FAQ)

**Q: 首次启动后端为什么会报错？**
A: 确保 PostgreSQL/Redis/Mosquitto 已通过 `docker compose -f docker/docker-compose.dev.yml up -d` 启动。

**Q: 开发时如何跳过认证？**
A: 不建议跳过。如需快速测试 API，在 Swagger UI 中点 Authorize 输入测试 token。

**Q: seed 数据在哪里？**
A: `src/EquipAI.Infrastructure/Seeding/DataSeeder.cs`，首次启动自动执行。

**Q: 如何重置数据库？**
A: `docker compose -f docker/docker-compose.dev.yml down -v` 会删除数据卷，重新 `up -d` 即可。

**Q: 为什么我的后台查询返回空？**
A: `IgnoreQueryFilters()` 加了吗？后台服务无 HttpContext → ITenantContext=Guid.Empty。

**Q: 如何测试告警触发？**
A: 用模拟器 `—anomaly-rate 20` 增加异常概率，或用 API 直接创建告警规则。

**Q: CI 本地能跑吗？**
A: 可以，配置好 .env 后 `act` (GitHub Actions 本地运行工具) 或按 CI 步骤手动执行。
