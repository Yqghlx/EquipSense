## 二、健康检查 (3 级探针)

| 探针 | 端点 | 检查内容 | K8s 兼容 |
|------|------|---------|---------|
| startup | /health/startup | PostgreSQL | start_period: 60s |
| liveness | /health | PostgreSQL + Redis | interval: 30s |
| ready | /health/ready | + MQTT + LLM | timeout: 10s, retries: 3 |

### 自定义检查

```csharp
MqttHealthCheck — TCP Connect 探活 (~1ms)
LlmHealthCheck — 只检查配置 (不发真实请求, 防止消耗 token)
```

### 容器级健康检查

| 服务 | 检查命令 | 间隔 |
|------|---------|------|
| postgres | pg_isready | 10s × 5 retries |
| redis | redis-cli ping | 10s × 5 retries |
| backend | curl /health/startup | 30s, start_period 60s |
| edgegateway | curl /health | 30s, start_period 15s |

## 三、Prometheus 指标 (29 后端 + 7 网关)

### 后端指标

| 分类 | 指标 | 类型 |
|------|------|------|
| 遥测 | equipai_telemetry_received_total | Counter (tenant_id, device_id) |
| | equipai_telemetry_dropped_total | Counter |
| | equipai_telemetry_rejected_total | Counter (reason) |
| | equipai_telemetry_deduped_total | Counter (source) |
| 告警 | equipai_alerts_evaluated_total | Counter (result, severity) |
| | equipai_active_alerts | Gauge (severity) |
| 工单 | equipai_workorders_created_total | Counter (type, priority) |
| | equipai_workorders_by_status | Gauge (status) |
| AI | equipai_analysis_requests_total | Counter (level) |
| | equipai_analysis_confidence | Histogram (10 buckets) |
| 连接 | equipai_mqtt_connected | Gauge |
| | equipai_signalr_connections | Gauge (tenant_id) |
| 证书生命周期 | equipai_certificate_expiry_timestamp_seconds | Gauge (certificate) |
| | equipai_certificate_days_until_expiry | Gauge (certificate) |
| | equipai_certificate_monitoring_status | Gauge (certificate) |

证书监控只读取 Nginx/MQTT 公钥，不挂载私钥；`CertificateMonitoringUnavailable`、7 天和 30 天告警由 Prometheus/Alertmanager 负责通知。运行时告警与 `validate-env.sh --check-runtime-files` 上线前门禁互为补充。

### 边缘网关指标

```
edgegateway_collections_total / collection_errors_total
edgegateway_buffer_queue_depth / upload_success_total / upload_fail_total
edgegateway_replay_messages_total
edgegateway_buffer_dropped_total (关键风险, 须≈0)
```

## 四、告警路由 (AlertManager)

| 级别 | 分组等待 | 重复间隔 | 通知 |
|------|---------|---------|------|
| Critical | 0s 立即 | 1h | Webhook |
| Warning | 5min 聚合 | 4h | Webhook |
| Info | — | — | 不通知 |

### 抑制规则

```
BackendDown → 抑制 business/performance 类别告警
MqttDisconnected → 抑制 HighTelemetryProcessingLatency
HighErrorRate → 抑制 AnalysisStalled / HighAnalysisLatency
```

## 六、数据库维护

| 策略 | 实现 | 调度 |
|------|------|------|
| TimescaleDB 压缩 | 7 天后自动压缩 (segmentby: tenant_id, device_id) | 自动 |
| TimescaleDB 保留 | 365 天 drop_chunks 兜底 | 自动 |
| 按租户精细清理 | TelemetryCleanupService 按套餐保留期 DELETE | 每天 3:00 |
| 审计日志清理 | LogRetentionCleanupService (365 天) | 每天 4:00 |
| 通知清理 | LogRetentionCleanupService (90 天) | 每天 4:00 |
| SQLite 缓冲 | 7 天清理 (CleanupOldAsync) | 每次回放后 |

## 七、备份恢复 (backup.sh)

```
PostgreSQL: docker exec pg_dump custom format → 容器内 pg_restore --list 完整性校验；恢复使用 TimescaleDB pre/post restore
Redis (可选): BGSAVE → docker cp dump.rdb
保留期: 7 天 (find -mtime +7 -delete)
异地: S3/OSS (可选, aws s3 sync)
通知: Webhook (可选)
```

## 八、启动脚本

| 脚本 | 用途 |
|------|------|
| bootstrap-production-secrets.sh | 仅补齐本地可随机生成的独立生产凭据；原子写入、重复键/并发/符号链接拒绝，门禁未通过时非零退出 |
| setup.sh | 一键配置 (.env → TLS → MQTT密码 → 完整性验证) |
| entrypoint.sh | 等待 PostgreSQL 就绪 (30 次重试) |
| generate-cert.sh | TLS 证书生成 |
| setup-mosquitto.sh | MQTT 密码文件 |

## 九、评估总结

| 维度 | 评分 | 说明 |
|------|------|------|
| 健康检查 | ⭐⭐⭐⭐⭐ | 3 级探针 + 4 类自定义 + JSON 结构化 |
| 指标系统 | ⭐⭐⭐⭐⭐ | 29 个后端自定义指标 + 7 个网关指标 + Histogram 多维度 + 证书生命周期告警 |
| 日志 | ⭐⭐⭐⭐⭐ | Serilog 结构化 + Seq 容器（已在 docker-compose） |
| 追踪 | ⭐⭐⭐⭐⭐ | OTel 全自动 + Jaeger 容器（已在 docker-compose） |
| 告警 | ⭐⭐⭐⭐⭐ | Prometheus 规则 + AlertManager 抑制/分级 + 可选外部 Webhook，未配置外部地址时 fail-safe 降级 |
| 部署脚本 | ⭐⭐⭐⭐⭐ | 4 个自动化脚本 + 健康依赖链 |
| 备份 | ⭐⭐⭐⭐⭐ | 完整备份 + 完整性校验 + 异地同步 |
| DB 维护 | ⭐⭐⭐⭐⭐ | 压缩+保留+聚合+按租户清理+日志清理 |
| 后台服务 | ⭐⭐⭐⭐☆ | 10 个 + 完整日志，Redis 分布式锁支持 token 条件续租和续租失败取消 |
