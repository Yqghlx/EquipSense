# EquipSense 风险登记册 (Risk Register)

> 全项目风险的统一视图，来源：全部评估报告中的风险项汇总  
> 评估标准：可能性(1-5) × 影响(1-5) = 风险值(1-25)

```
🟡 中 (4-7) → 需规划缓解

```

| C64 | 告警站内通知按租户一次性加载全部运维收件人，并一次性跟踪通知/邮件任务，告警扇出规模增长可能造成内存峰值或长事务 | 收件人按用户 UUID 稳定分页，每批最多 500 条，每批将站内通知和邮件任务原子提交后清理跟踪器；每批仍按 EventId 幂等查询，数据库唯一索引继续兜底；新增 501 收件人全量写入与分页 SQL 回归；真实大租户通知事务耗时和邮件积压容量仍待上线前基线 | 本轮工作区 |
| C65 | SignalR/Web Push 通知按租户一次性解析全部用户偏好并组播，且推送批次清理整个 EF 跟踪器可能误删调用方暂存的站内通知 | SignalR 收件人、偏好筛选、组播和 Push 用户列表均按用户 UUID 稳定分页，每批最多 500 条；站内通知按批提交；Push 仅分离自身订阅实体，不调用全局 `ChangeTracker.Clear`；新增 501 用户端到端扇出与待提交通知保留回归；真实 SignalR 集群组播、Web Push 限流/重试和大租户耗时仍待部署侧验收 | 本轮工作区 |
| C66 | 审批待办查询一次性加载当前租户所有候选审批记录，未指定审批人的工单规模增长可能造成请求内存峰值和长查询 | 待办按显式租户/状态/指定审批人过滤，以 `WorkOrderApproval.Id` 稳定游标每批最多读取 500 条，使用 `AsNoTracking` 和最小投影；角色在租户范围内规范化，完整结果按步骤顺序返回；新增 501 条 SQLite `LIMIT` 回归；真实 PostgreSQL 查询计划、待办响应体大小和大租户容量仍待部署侧验收 | 本轮工作区 |
