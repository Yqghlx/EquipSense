### EquipSense 的差异化

| 维度 | 巨头 (ThingWorx/Maximo) | 国内平台 | EquipSense |
|------|------------------------|---------|------------|
| 部署复杂度 | 高，需要专业团队实施 | 中高 | **低**，Docker Compose 一键部署 |
| 定价 | 数十万-数百万/年 | 中高 | **可灵活定价** |
| 功能覆盖 | 全面但臃肿 | 偏重连接或偏重分析 | **闭环完整**：遥测→告警→AI→工单→知识 |
| AI 能力 | 依赖外部 AI 平台 | 规则为主 | **四级自动降级**，LLM 可选 |
| 工单集成 | 有但偏重 EAM | 有 | **可插拔**：独立/钉钉/飞书/Webhook/EAM |
| 边缘网关 | 有但闭源 | 部分有 | **开源可定制**，OPC UA + Modbus |
| 多租户 | 企业级部署 | 有限 | **Day 1 SaaS 架构** |
| 安装运维 | 专业团队 | 需技术支持 | **15 分钟上手** |
| 代码开源 | ❌ 闭源 | ❌ 闭源 | 可开源或开放核心 |

**核心差异化总结**：
1. **轻量级**：不绑定硬件，不强推替换现有系统，可 Docker 一键部署
2. **闭环完整**：不是单纯的监控面板，而是从采集 → 告警 → AI 分析 → 工单 → 知识沉淀的完整闭环
3. **可插拔工单**：客户可以继续用现有的工单系统（Maximo、EAM），也可以用 EquipSense 自带的
4. **四级 AI 降级**：不是"没 AI 就完蛋"，数据不好时自动降级规则，LLM 挂了也不影响核心功能

## 三、目标客户画像

### 一级目标 (PMF 最容易)

```
中小型制造业工厂
├── 设备数: 20-500 台
├── 年 IT 预算: 50-500 万
├── 痛点: 设备故障停机损失大、缺乏数字化手段
├── 现状: 可能有 PLC/SCADA 但没连接
└── 决策: 老板直接拍板，不需要集团采购
```

**典型场景**：
- 某注塑厂有 50 台注塑机，经常突然停机，维修靠"出问题了打电话叫师傅"
- 某 CNC 加工厂有 200 台数控机床，每月因刀具磨损导致的废品率 5%
- 某空压机站有 15 台空压机，电费占比 30% 且缺乏能效管理

### 二级目标 (增长)

```
中型制造企业 / OEM 设备厂商
├── 设备数: 200-2000 台
├── 年 IT 预算: 500-2000 万
├── 痛点: 需要给客户提供远程运维能力
├── 现状: 有 IT 团队，可能有 MongoDB/MySQL 做简单记录
└── 决策: 需要技术评估 + 采购流程
```

### 三级目标 (高客单价)

```
大型工厂 / 集团 / 政府项目
├── 设备数: 2000+ 台
├── 年 IT 预算: 2000 万+
├── 痛点: 等保合规、政策要求数字化转型
└── 决策: 长周期采购 (6-12 个月)
```

## 四、商业模式

### 方案 A: SaaS 订阅 (推荐起步)

| 套餐 | 设备数 | 用户数 | 保留期 | 价格（参考） | 目标客户 |
|------|--------|--------|--------|------------|---------|
| 社区版 (免费) | ≤10 | ≤3 | 7 天 | ¥0 | 个人/试用 |
| Starter | ≤50 | ≤10 | 90 天 | ¥2,000/月 | 小型工厂 |
| Professional | ≤200 | ≤50 | 180 天 | ¥8,000/月 | 中型工厂 |
| Enterprise | 不限 | 不限 | 365 天 | ¥30,000+/月 | 大型客户 |

> 📌 **定价口径说明**：本表为早期市场分析阶段的参考定价。**正式定价以 [S13-产品化路线图 §8.2](./S13-产品化路线图.md) 为准**（Starter ¥1,500/月 · Standard ¥3,000/月 · Premium ¥8,000/月，含首年特价）。下方收入估算基于本表参考价，仅作量级演示。

**收入估算（保守）**：
```
10 个 Starter  × ¥2,000 = ¥20,000/月
 5 个 Professional × ¥8,000 = ¥40,000/月
 2 个 Enterprise × ¥30,000 = ¥60,000/月
─────────────────────────────────
合计: 17 个客户 → ¥120,000/月 → ¥144 万/年
```

### 方案 B: 开放核心 + 企业版 (推荐长期)

```
开源社区版 (AGPLv3)
  ├── 核心功能: 设备管理/告警/工单/实时推送
  ├── 限制: 10 设备、3 用户、社区支持
  └── 目的: 获取用户、建立生态、口碑传播

企业版 (商业许可)
  ├── 全部功能: 无限制
  ├── + 企业级集成 (钉钉/飞书/EAM)
  ├── + 技术支持 + SLA
  ├── + 私有部署 (可离线)
  └── 目的: 主要收入来源

增值服务
  ├── 实施/部署咨询 (¥5-20 万/项目)
  ├── 定制开发 (¥1,000/天)
  ├── AI 训练调优 (¥10 万/模型)
  └── 边缘网关硬件套装 (¥5,000-20,000/套)
```

### 方案 C: 项目制交付

面向政府/大型企业的定制化交付项目：
- 单项目 ¥30-200 万
- 包含本地部署 + 定制开发 + 培训
- 风险：人效比低、可复制性差
- 适合：品牌背书 + 现金流补充

### 推荐组合: B + C

```
稳定现金流 ← 企业版 SaaS 订阅 (ARR)
口碑传播  ← 开源社区版 (用户增长)
利润补充  ← 项目制交付 (品牌背书)
生态构建  ← 边缘网关硬件 (渠道绑定)
```

|------|------|----------------|

| MQTT Broker | 2C 4G | ¥400 |
| 前端 | 2C 4G | ¥400 |
| Prometheus/Grafana | 2C 4G | ¥400 |
| 带宽 | 100Mbps | ¥500 |
| **合计** | | **¥6,200/月** |

### 毛利率估算

```
SaaS 月收入: ¥120,000/月 (17 个客户)
服务器成本:  ¥6,200/月
毛利率:      ~95%

加入人力成本:
  1 个后端 + 1 个前端 + 1 个运维 ≈ ¥70,000/月
  运营利润率: (120,000 - 6,200 - 70,000) / 120,000 ≈ 36%
```

**结论**：17 个付费客户即可打平小型团队成本。

## 六、市场时机判断

### 有利因素

| 因素 | 说明 |
|------|------|
| 市场规模 | 全球预测维护市场 CAGR 15-25%，空间巨大 |
| 政策驱动 | 国务院"工业互联网"国家战略，2025 年核心产业 1.27 万亿 |
| 数字化转型 | 中国制造业企业数字化率仍低，增量空间大 |
| 竞争格局 | 国际巨头价格高、实施重；国内产品偏重连接或偏重分析，缺少完整闭环 |
| AI 落地 | LLM 的普及让"AI 根因分析"从奢侈品变为必需品 |
| 技术成熟 | .NET 8 + React 19 + TimescaleDB 技术栈成熟稳定 |
| 部署门槛低 | Docker Compose 一键部署，15 分钟即可体验 |
| 开源趋势 | 企业越来越倾向开放核心 + 企业版的采购模式 |
| 边缘计算 | 5G + 边缘 AI 推动工业现场算力下沉，利好边缘网关 |
| 国产替代 | 信创政策推动国产工业软件替代，利好国内自研平台 |

### 风险因素

| 风险 | 说明 |
|------|------|
| 市场竞争激烈 | PTC/IBM/SAP 等巨头已在布局，国内树根/用友等也在抢市场 |
| 获客成本高 | 工业客户决策链长，从接触到签单通常 3-12 个月 |
| 需要行业 Know-how | 设备类型不同，告警规则和分析模型差异大 |
| 单点开发者 | Bus Factor = 1，投资方和客户都会关注 |
| 缺少行业案例 | 零客户、零收入、零案例，说服客户有难度 |
| 数据积累不足 | AI 模型需要真实故障数据训练，新平台数据积累需要时间 |
| 开源风险 | 如果走开源路线，大公司可能白嫖社区版 |
| 运维责任 | 工业停机会导致生产损失，SLA 压力大 |

## 八、可行建议路径

### 阶段 1: PMF 验证 (0-6 个月)

```
目标: 找到 3-5 个愿意付费的早期客户

行动:
  1. 包装成 Docker 一键部署体验版
  2. 在制造聚集区（东莞/苏州/宁波）找 3-5 个工厂做试点
  3. 免费试用 3 个月，换取使用反馈 + 案例背书
  4. 收费策略：先用低成本方案 A (Starter ¥2,000/月) 验证支付意愿
```

### 阶段 2: 产品市场匹配 (6-18 个月)

```
目标: 50 个付费客户, ARR ¥500 万+

行动:
  1. 基于早期客户反馈迭代产品
  2. 聚焦 2-3 个垂直行业（CNC/注塑/空压机）做深
  3. 构建行业知识库（预置 50+ 设备类型模板和告警规则）
  4. 发布开源社区版，吸引开发者关注
  5. 补充团队（至少 +1 个懂的工业的人）
```

### 阶段 3: 规模扩张 (18-36 个月)

```
目标: 500+ 客户, ARR ¥5,000 万+

行动:
  1. 建立销售团队 + 渠道体系（系统集成商）
  2. 边缘网关硬件化（预装软件的硬件网关）
  3. 行业 SaaS 化（按设备类型拆为独立产品线）
  4. AI 模型市场（预训练模型 + 客户数据微调）
```

## 九、最终判断

**能赚钱。赛道对、时机对、产品架构对。**

- ✅ **赛道**：千亿级市场，CAGR > 20%
- ✅ **时机**：AI 落地 + 国产替代 + 中小企业数字化转型三浪叠加
- ✅ **产品**：架构完整（采集→告警→AI→工单→知识），技术栈现代
- ✅ **差异化**：比国际巨头轻、比国内平台全、比闭源方案透明
- ❓ **关键在于**：找到第一批付费客户，验证 PMF

**最大的不确定因素不是"技术能不能做"，而是"卖不卖得出去"。** 项目底子很好——约 4 周（5/31–6/27）独立完成全平台并产出 28 份评估文档证明工程能力扎实——但商业化成功需要的是产品思维 + 行业人脉 + 销售执行力，这三样单靠写代码拿不到。

如果目标是**做一家公司**，建议立即启动阶段 1，找 3 个工厂老板喝咖啡比再写 3 个月代码更有价值。如果目标是**技术作品展示**或**面试谈资**，现在的程度已经远超"能打动面试官"的水平了。
