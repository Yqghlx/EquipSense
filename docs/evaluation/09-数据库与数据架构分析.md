# EquipSense 数据库与数据架构专项分析报告

> 分析日期：2026-07-02（数据校正） · 范围：29 实体配置 · 22 次迁移 · TimescaleDB 超级表

---

## 一、数据库总体架构

```
PostgreSQL 16 + TimescaleDB 2.x
├── 业务表 (29 个 EF Core 实体) ← 常规表, 含 tenant_id 全局过滤
├── 时序表 (1 个)               ← TimescaleDB 超级表, 窄表设计
├── 连续聚合 (1 个)             ← telemetry_hourly 小时级统计
└── 迁移历史 (22 次, 45 文件)   ← EF Core Code-First Migrations
```

### 数据流向

```
边缘网关 MQTT → TelemetryService 入库 → device_telemetry (TimescaleDB)
  └→ TelemetryReceivedEvent → AlertEvaluationService → alerts
    └→ AlertTriggeredEvent → RootCauseAnalysisEngine → analyses
      └→ AnalysisCompletedEvent → WorkOrderService → work_orders
```

## 三、时序数据 (TimescaleDB)

### DeviceTelemetry — 窄表设计

```csharp
public class DeviceTelemetry
{
    public DateTime Time { get; set; }      // 采集时间戳
    public Guid TenantId { get; set; }
    public Guid DeviceId { get; set; }
    public string Metric { get; set; }      // 指标名 (如 "temperature")
    public double? Value { get; set; }      // 数值
    public string? StringValue { get; set; } // 文本值 (预留)
    public string Quality { get; set; }     // "good"/"warning"/"bad"
    public string Source { get; set; }      // "mqtt"/"http"
}
// 无主键! TimescaleDB 自动管理分区
```

### 超级表初始化

```sql
-- 1 天块间隔
SELECT create_hypertable('device_telemetry', 'time',
    chunk_time_interval => INTERVAL '1 day');

-- 索引 (用于查询加速)
CREATE INDEX idx_telemetry_tenant_device_time
    ON device_telemetry (tenant_id, device_id, time DESC);
CREATE INDEX idx_telemetry_tenant_device_metric
    ON device_telemetry (tenant_id, device_id, metric, time DESC);

-- 7 天后自动压缩 (按 tenant_id, device_id 分段)
ALTER TABLE device_telemetry SET (
    timescaledb.compress,
    timescaledb.compress_segmentby = 'tenant_id, device_id',
    timescaledb.compress_orderby = 'time DESC'
);
SELECT add_compression_policy('device_telemetry', INTERVAL '7 days');

-- 全局保留: 365 天 (取最大套餐)
SELECT add_retention_policy('device_telemetry', INTERVAL '365 days');
```

### 小时级连续聚合

```sql
CREATE MATERIALIZED VIEW telemetry_hourly
WITH (timescaledb.continuous) AS
SELECT
    time_bucket('1 hour', time) AS bucket,
    tenant_id, device_id, metric,
    AVG(value) AS avg_value,
    STDDEV(value) AS std_dev,
    MIN(value), MAX(value),
    COUNT(*) AS sample_count,
    PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY value) AS p95_value
FROM device_telemetry
GROUP BY 1, 2, 3, 4 WITH NO DATA;

-- 每小时刷新 (3 小时前到 1 小时前)
SELECT add_continuous_aggregate_policy('telemetry_hourly',
    start_offset => INTERVAL '3 hours',
    end_offset => INTERVAL '1 hour',
    schedule_interval => INTERVAL '1 hour');
```

### 已知性能索引 (6/22 AddPerformanceIndexes)

```csharp
// v1.5 性能加固：工单列表分页排序索引
// 命中 WorkOrderService.GetWorkOrdersAsync 的高频查询：
//   WHERE tenant_id = ? [AND status = ?] ORDER BY created_at DESC LIMIT ? OFFSET ?
```

## 六、反规范化与一致性保障

| 反规范化字段 | 写入点 | 风险 |
|-------------|--------|------|
| Tenant.CurrentDeviceCount | 设备创建/删除 | 并发更新可能偏移 |
| Tenant.CurrentUserCount | 用户创建/停用/激活 | 需事务保护 |
| Alert.TriggerCount | 每次更新告警 | 幂等写入 |
| KnowledgeRule.SuccessCount | 规则匹配成功 | 后台增量更新 |

**已修复的 Bug**：停用用户时未 `CurrentUserCount--` → 配额卡死无法建新账号 (#d969572)
