## 二、测试金字塔现状

```
        ┌──────────────┐
        │  E2E (344)   │   30% — Playwright (52 spec, 8 categories)
        ├──────────────┤
        │ 集成 (86)    │    8% — xUnit + Testcontainers (26 files)
        ├──────────────┤
        │ 单元 (700)   │   62% — NUnit 442 + Vitest 258
        └──────────────┘
```

### 理想测试金字塔 (Google 推荐)

```
        ┌──────────────┐
        │  E2E  (10%)  │  少量核心链路
        ├──────────────┤
        │ 集成 (20%)   │  API 层 + DB
        ├──────────────┤
        │ 单元 (70%)   │  服务 + 工具 + 组件
        └──────────────┘
```

**结论**：当前呈"不倒翁"型 — E2E 占比过高 (30%)。E2E 测试维护成本高、运行慢 (~30min)、且容易 flaky。

**建议调整目标**：
```
E2E → 15% (保留核心链路+安全测试)
集成 → 25% (覆盖全部 30 个 Controller)
单元 → 60% (补充领域层测试)
```

### 3.2 测试模式

```csharp
// 标准模式: FluentAssertions + Moq + AAA (Arrange/Act/Assert)
public class UsageLimitMiddlewareTests
{
    [Fact]
    public async Task NonPost_ShouldBypassUsageCheck()
    {
        // Arrange
        var context = CreateContext(method: "GET");
        var middleware = new UsageLimitMiddleware(...);

        // Act
        await middleware.InvokeAsync(context);

        // Assert
        context.Response.StatusCode.Should().Be(200);
    }
}
```

### 3.3 缺点

- **NUnit/xUnit 混用**：单元测试用 NUnit，集成测试用 xUnit。建议统一为 xUnit
- **领域层测试不足**：`RootCauseAnalysisEngine` 的核心降级逻辑测试不多
- **边缘网关测试覆盖低**：协议适配器单元测试但无集成测试

### 6.2 安全测试覆盖

```
SQL 注入         ─ POST body 含 "OR 1=1" → 期望 400
XSS 注入         ─ POST body 含 "<script>" → 期望 400
超长输入         ─ 100KB payload → 期望 400
损坏令牌         ─ 无效 JWT → 期望 401
速率限制         ─ 高频请求 → 期望 429
离线队列         ─ 断开网络 → 操作入队 → 恢复 → 同步
```
