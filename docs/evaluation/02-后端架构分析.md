### 3.2 InMemoryEventBus 深度分析

```csharp
Channel<IIntegrationEvent> — BoundedChannel(1000, DropOldest)
├── SingleReader = true      (单消费者, 保证 FIFO)
├── SingleWriter = false     (多生产者可同时发布)
└── FullMode = DropOldest    (满时丢弃最旧, 防 OOM)

后台消费者 ConsumeAsync():
  await foreach (var @event in _channel.Reader.ReadAllAsync(_cts.Token))
    using var scope = _serviceProvider.CreateScope();  // 每事件独立 DI Scope
    foreach (var handlerType in handlerTypes)
      reflection dispatch HandleAsync(@event, ct)       // 反射分发
      catch(Exception) → LogError(handler error)        // 错误隔离
```

**设计权衡**：

| 特性 | 现状 | 长期方案 |
|------|------|---------|
| 可靠性 | 进程内，重启丢失 | RabbitMQ (持久化队列) |
| 重试 | 无 | 死信队列 + 重试策略 |
| 顺序保证 | 单 Consumer 保证 FIFO | 分区键保证有序 |
| 容量 | 1,000 条环形缓冲 | 可配置（建议先扩容到 10,000） |
| 分布式 | 单进程 | RabbitMQ 集群 |

### 3.3 告警评估引擎完整流程

```
MQTT → TelemetryService (入库)
  → TelemetryReceivedEvent 发布
    → TelemetryEventHandler.HandleAsync()
      ├── 1. UpdateDevicePresenceAsync()
      │     状态=Online, LastSeenAt=now (仅在非 Online 时写 DB)
      │
      └── 2. EvaluateForDeviceAsync()
            ├── 查 MetricBaseline (IFQF + 显式 TenantId)
            ├── 查 DeviceType (IFQF)
            ├── 查 AlertRule (TenantId + Metric + DeviceId + DeviceType)
            │
            ├── 遍历规则 → 匹配 IAlertRuleEvaluator
            │    ├── ThresholdEvaluator  (静态阈值比较)
            │    ├── BaselineEvaluator   (3-sigma 偏离)
            │    └── CombinedEvaluator   (多条件 AND)
            │
            ├── 触发? → AlertAggregator.Evaluate()
            │    ├── 第 1 次 → CreateAlertAsync → Publish(AlertTriggeredEvent)
            │    ├── 第 2-3 次 → UpdateExistingAlertAsync
            │    └── >3 次 → 静默
            │
            └── 未触发? → TryAutoResolveAsync()
                 └── 有 Active 告警? → 自动 Resolve
```

### 3.4 工单完整状态机

```
PendingDispatch ─→ Assigned ─→ InProgress ─→ Completed ─→ Accepted ─→ Closed
        │              │             │              │             │
        ├─ Cancelled ←─┘        ┌────┘        ┌─────┘        (终态)
        │                       │             │
        │                  SubmittedFor    Rejected
        │                  Approval         │
        │                       │           └─→ InProgress (返工)
        │                   ┌───┘
        │                   ▼
        │              Accepted
        │              (审批通过，与直接验收同逻辑)
        │
        └──── 合法转换矩阵 — 硬编码校验
              PendingDispatch → {Assigned, Cancelled}
              Assigned → {InProgress, Cancelled}
              InProgress → {Completed, Cancelled, SubmittedForApproval}
              Completed → {Accepted, Rejected, SubmittedForApproval}
              SubmittedForApproval → {Accepted, InProgress}
              Accepted → {Closed}
              Rejected → {InProgress}
              Closed / Cancelled → (终态)
```
