# 从技术到商业：90 天行动方案

> 面向一个没有销售团队、没有行业人脉、没有融资的独立开发者  
> 目标：90 天内验证"有人愿意为这个产品付钱"

---

## 核心理念

```
代码写得再好，没有客户愿意付钱 = 0
代码一般般，有 3 个客户愿意付钱 = 商业验证成功

所以前 90 天唯一的目标不是"完善产品"，而是"找到第一个付钱的人"
```

### 三个关键假设（需要验证）

| 假设 | 验证方式 | 通过标准 |
|------|---------|---------|
| 工厂有设备停机痛点 | 和 10 个工厂老板聊过 | ≥5 个人说"这确实是个问题" |
| 我们的产品能解决 | 有人愿意试用 | ≥3 个工厂部署了试用版 |
| 有人愿意付钱 | 有人真的付钱 | ≥1 个客户付了 ≥¥2,000/月 |

---

## 时间线总览

```
第 1-2 周 ── [P0 修复]    修复客户会关心的技术硬伤
                   制作 demo / 销售材料
                   确定第一批目标客户清单

第 3-6 周 ── [冷启动]     联系 50+ 潜在客户
                   争取 3-5 个免费试用
                   安装并跟进试用反馈

第 7-12 周 ─ [验证]      试用 → 付费转化
                   如果没人付钱 → 诊断问题或 pivot
                   如果有人付钱 → 制定下一阶段计划

                   里程碑: 第 12 周末 → 决定全职还是找份工作
```

## 第 1-2 周：把产品收拾到"能卖"的程度

### 1.1 必修的 P0 问题（不修客户不会买）

| 问题 | 原因 | 工作量 | 优先级 |
|------|------|--------|--------|
| MQTT 传输未加密 | 客户的安全部门会打回 | **2 天** | ⭐⭐⭐⭐⭐ |
| InMemoryEventBus 扩容 1000→10000 | 演示时压力一大就丢数据 | **1 天** | ⭐⭐⭐⭐ |
| NuGet CVE | 安全审计过不了 | **2 天** | ⭐⭐⭐⭐ |
| 安装文档 | 不能指望客户看代码 | **2 天** | ⭐⭐⭐⭐⭐ |

**关键产出**：一个别人拿到后能在 30 分钟内跑起来的包。

### 1.2 制作 Demo 环境

```
目标: 客户不需要装任何东西，点开链接就能看到效果

行动:
  1. 买一台便宜的云服务器 (阿里云 2C4G ≈ ¥200/月)
  2. 部署完整的环境 (模拟 10 台设备在运行)
  3. 预先注入一些数据:
     - 5 台正常运行的设备 (温度/振动/压力)
     - 2 台有异常趋势的设备 (缓慢升温)
     - 1 台有活跃告警的设备 (超过阈值)
     - 2 个已处理的工单 (展示闭环)
  4. 准备一个"客户故事"页面 (不是功能列表!)
```

### 1.3 准备销售材料（而不是产品文档）

```
❌ 不要写:
  - "基于 .NET 8 的模块化单体架构"
  - "支持 OPC UA 和 Modbus TCP/RTU"
  - "使用 PostgreSQL 16 + TimescaleDB"

✅ 要写:
  - "每年帮工厂减少 30% 的意外停机"
  - "您的设备出现异常时，系统自动派工给维修师傅"
  - "安装只需要 15 分钟，不影响现有产线"
```

**一份销售一页纸就够了**：
```
┌──────────────────────────────────────────────┐
│  EquipSense — 设备不再"突然坏掉"               │
│                                              │
│  痛点: 设备意外停机 → 停产损失 → 维修费用高     │
│  方案: 实时监控 → AI 预警 → 自动派工            │
│                                              │
│  数字说话:                                    │
│  · 减少 30% 意外停机  (行业平均)                │
│  · 降低 20% 维修成本   (行业平均)               │
│  · 安装只要 15 分钟                             │
│                                              │
│  客户案例: (空 — 当你还没有客户，就放产品截图)   │
│                                              │
│  免费试用 30 天，不需要信用卡                    │
└──────────────────────────────────────────────┘
```

### 1.4 确定第一批目标

```
不要撒网，聚焦一个你能触及的细分领域

如果你是:
├── 老家有工厂 → 就从老家开始
├── 前同事在制造业 → 从他开始
├── 认识做设备代理的人 → 从他开始
└── 以上都没有 → 从"注塑机"或"CNC"或"空压机"开始

选择标准:
  1. 设备停机确实是个问题 (不是"有了更好")
  2. 决策者能接触到 (不是必须走集团采购)
  3. 你有办法找到他们 (通过朋友圈/行业协会/展会)
```

**第一批目标清单至少 50 个名字**（从今天开始列）。

## 第 3-6 周：找到愿意让你"试一试"的人

### 2.1 你要找的是谁（画像精确到岗位）

不要找"企业"，要找具体的人：

```
✅ 对的联系人:
  - 工厂设备主管 / 设备部长
  - 工厂厂长 (小厂老板直接兼)
  - 设备代理商的技术负责人
  - 园区管委会负责企业服务的

❌ 不要找:
  - CIO / CTO (你进不去)
  - 采购部 (他们只走流程)
  - 集团总部 (决策链太长)
```

### 2.2 怎么找到他们（三个渠道就够了）

```
渠道一: 你已有的圈子
  ├── 发一条朋友圈: "做了一个工业设备监控系统，想找 3 个工厂免费试用"
  ├── 私信 20 个你觉得可能认识工厂的人
  └── 预期: 从已有圈子拿到 2-3 个引荐

渠道二: 行业展会/活动
  ├── 搜索你所在城市最近的工业自动化展、机床展
  ├── 不需要展位，买张门票进去和人聊就行
  └── 预期: 一场展会产生 5-10 个潜在客户微信

渠道三: 找到聚集区直接跑
  ├── 东莞长安 (模具/五金)
  ├── 苏州昆山 (电子/机械)
  ├── 宁波慈溪 (家电/模具)
  ├── 找到工业园，直接走进门卫问设备部在哪
  └── 预期: 一天跑 10-15 家，拿到 3-5 个联系方式
```

### 2.3 怎么聊（30 秒电梯演讲）

```
❌ 错误: "我是做工业互联网平台的，基于 AI 和大数据的预测性维护..."
✅ 正确: "你们的设备有没有突然停机的烦恼？我有个工具可以在出问题之前提前预警。"

然后: 闭嘴，听对方说。

"有啊，上个月我们那台注塑机突然停了，损失了 20 万..."
→ 你已经成功引起兴趣了。

"没有，我们设备很稳定"  
→ 这不是你的客户，礼貌结束，找下一家。
```

### 2.4 免费试用的条件

不要无偿送出去。免费要有门槛：

```
免费试用 30 天，条件:
  ✅ 客户提供一个真实的设备接入 (给客户面子，你拿到真实数据)
  ✅ 试用结束后安排 15 分钟的反馈电话 (你拿到改进方向)
  ✅ 如果觉得有用，帮忙介绍一个同行 (你拿到潜在客户)

❌ 不满足的条件不要做:
  - 不要免费提供定制开发 (你会被拖死)
  - 不要免费提供服务期超过 3 个月 (会消磨付费意愿)
  - 不要免费给大公司 (大公司没有"免费试用"这种采购项)
```

### 2.5 本周指标

```
联系 50 个潜在客户
  → 10 个愿意聊一聊
    → 5 个同意免费试用
      → 3 个实际部署了
```

## 第 7-12 周：验证是否有人愿意付钱

### 3.1 试用期管理

```
第一周: 帮客户装好，确保正常运行
第二周: 检查数据，看一下告警有没有触发
第三周: 约 15 分钟电话，问 2 个问题:
  1. "有没有发现什么之前不知道的问题？"
  2. "有没有因为预警避免了停机？"
第四周: 谈付费

如果客户主动说"这个挺好用的" → 你已经有产品价值了
如果客户说"还在看" → 问题可能出在:
  - 安装太复杂 (客户没用上)
  - 告警阈值没调好 (全是误报或全没报)
  - 客户没有真正的痛点 (选错客户了)
```

### 3.2 谈付费

```
话术:
"您用了这一个月，觉得有用吗？"
"如果每天花 60 块钱（¥2,000/月 ÷ 30 天），让设备不再突然停机，划算吗？"

价格:
  Starter: ¥2,000/月 (首年特价 ¥1,500/月)
  年付优惠: 送 2 个月 (¥1,700/月 × 10)

底线:
  第一年只要能收到 ¥1,000/月 就签
  目的是拿到"有人愿意付钱"这个证据
  钱多钱少是第二阶段的事
```

### 3.3 做好被拒绝的准备（常见的拒绝理由）

| 拒绝理由 | 真正的意思 | 你应该怎么做 |
|---------|-----------|------------|
| "我们回去研究一下" | 没兴趣 | 一个月后跟进一次，没有就放弃 |
| "我们需要走采购流程" | 大公司，你进不去 | 要么接受 3-6 个月周期，要么放弃 |
| "我们的设备很稳定" | 没有痛点 | 下次找客户时改善筛选标准 |
| "你太贵了" | 没看到价值 | 先帮客户解决一个具体问题再谈价 |
| "我们已经有供应商了" | 你不够特别 | 问"现在用的怎么样？"找到他的不满 |
| "我想再对比一下" | 在犹豫 | 提供限时免费期制造紧迫感 |

### 3.4 三个可能的结局

```
第 12 周结束时:

结局 A: ≥1 个客户付了钱
  └── ✅ PMF 初步验证
  └── 下一步: 
      └── 全职投入
      └── 扩团队 (至少 +1 个能卖的人)
      └── 融资 (拿着客户和收入数据去找天使)

结局 B: 没人付钱，但有 3+ 个客户在积极用且反馈正面
  └── ✅ 产品有价值，但付费意愿不足
  └── 问题可能出在定价/包装/付费习惯
  └── 下一步:
      └── 调整定价 (更低或按效果付费)
      └── 或者 pivot 到"免费增值"模式
      └── 再试 90 天

结局 C: 没人用，没人感兴趣，找到不到客户
  └── ❌ 对这个特定市场假设不成立
  └── 下一步:
      └── pivot (换个细分市场)
      └── 或者把这个项目作为作品开源
      └── 拿着这个项目去找份工作 (含金量极高)
```

## 现实检验：你需要具备的能力

| 能力 | 必要程度 | 如果你不会 |
|------|---------|-----------|
| 冷启动销售（陌生拜访/电话） | ⭐⭐⭐⭐⭐ | 找一个互补的合伙人，或者放弃商业化 |
| 产品演示（不要讲技术，要讲场景） | ⭐⭐⭐⭐⭐ | 找朋友练，练到能在 1 分钟内说清楚 |
| 抗拒绝能力（90% 的人会拒绝你） | ⭐⭐⭐⭐ | 提前准备好话术，被拒是常态 |
| 快速迭代（根据反馈调产品） | ⭐⭐⭐⭐ | 这是你的强项，继续保持 |
| 简单财务（发票/合同/收款） | ⭐⭐⭐ | 注册个体户即可，¥500 搞定 |

**诚实评估**：如果你是一个"纯技术"的人，从 0 开始卖东西会非常痛苦。一个更现实的路径是：**先用这个项目敲开一份相关工作的门**（工业软件产品经理/架构师/技术合伙人），在工作中积累行业人脉和销售认知，再考虑出来创业。

## 最后的话

你已经做出了一个 23 万行的完整工业 IoT 平台。**技术能力已经充分证明过了。**

但赚钱需要的不是更好看的代码，而是**找到一个人愿意为它掏钱**。这件事做代码的思路完全不同——没有"写完 deploy"就完成的时刻，它需要的是**每天被人拒绝 5 次还能笑着继续**的心理素质。

如果你准备好了，就从今天列 10 个人的名单开始。如果还没准备好——这个项目已经是一个极好的面试作品了，用它找份好工作完全没有问题。

无论哪条路，之前的 25 份评估文档已经为你把"技术上的自己"整理清楚了。
