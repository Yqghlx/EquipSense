## 三、已知 CVE 与漏洞状态

### 3.1 NuGet 漏洞

`Directory.Build.props` 已启用 `TreatWarningsAsErrors=true`，仅保留与版本自动解析有关的 `NU1603`；`NU1901`/`NU1903` 不再抑制。CI 显式执行：

```bash
dotnet list EquipAI.sln package --vulnerable --include-transitive
```

2026-08-13 使用 NuGet 官方源联网复核：`EquipAI.sln` 中 6 个源码项目与 2 个测试项目均未发现已知漏洞包，命令以 0 退出。AutoMapper 保持在 15.1.3；不得为规避许可证降级，因为所有低于 15.1.1 的版本受高危递归拒绝服务漏洞影响。生产环境通过 `AutoMapper__LicenseKey` 注入供应商密钥，应用启动门禁和 `docker/validate-env.sh` 会拒绝缺失、占位或过短值。参考 [GHSA-rvv3-g6hj-g44x](https://github.com/advisories/GHSA-rvv3-g6hj-g44x)。

前端同时执行生产依赖精确例外审计和全量 `npm audit --audit-level=high`。审计脚本已验证 npm 返回的是完整漏洞报告；漏洞源网络/鉴权失败时会阻断流水线，不能再被误报成“零漏洞”。2026-08-13 分别执行生产依赖审计和完整锁文件审计，二者均以 0 退出；完整报告覆盖 914 个解析依赖，其中 npm 统计的生产依赖 123 个、开发依赖 792 个，所有严重级别漏洞计数均为 0。

### 3.2 Trivy 镜像扫描

CI 对 main 镜像和版本发布镜像均使用 `exit-code: '1'` 扫描 `HIGH,CRITICAL`，发现漏洞即阻断；`ignore-unfixed: true` 保留为当前风险接受策略。当前 workflow 先将三张镜像加载到 runner，全部通过扫描后直接逐标签推送同一批本地镜像，不再执行第二次 Buildx；扫描与推送对象的一致性由 CI 契约测试锁定，首次真实 tag run 仍需验收。

### 3.3 CI Action 与发布供应链

2026-08-13 修复后对 `.github/workflows/ci.yml` 和 `.github/workflows/codeql.yml` 的静态盘点为 38 次 Action 调用，全部固定到经官方仓库核实的完整 commit SHA。高权限暴露面已按 job 收敛：读取生产 SSH 私钥的部署 Action仅位于部署 job，Docker Action仅位于 `packages: write` 镜像 job，CodeQL Action仅位于 `security-events: write` 分析 job；顶层默认令牌为只读。

版本发布已拆为两个最小权限边界：镜像 `release` job 仅拥有 `contents: read` 与 `packages: write`，独立 `create-release` job 仅拥有 `contents: write`，并由 `deploy` 等待二者成功。NuGet/npm 当前为 0 漏洞不能替代 CI 执行链本身的供应链治理；真实 tag run 仍需验证 GitHub 仓库设置、GHCR 推送和 Release API 的运行态行为。
