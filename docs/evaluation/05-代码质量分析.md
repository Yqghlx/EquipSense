## 二、错误处理模式

### 后端三层

```
全局异常中间件: 401/404/409/400/500 统一 {code, message, details}
业务层 catch: LogWarning(4xx) / LogError(5xx) + 降级回退 (LLM/配置/离线)
前端 7 级: 无响应/403/404/429/500/502/503/504 各含中文 Toast
```

### 反模式审查

| 反模式 | 计数 | 说明 |
|--------|------|------|
| async void | 0 | 全部 460 个 async 方法正确返回 Task |
| .Wait()/.Result | 3 | 全在停机路径，IApplicationLifetime 不支持 async |
| 空 catch | 4 | 全在 EdgeGateway Dispose 路径，可接受 |
| 异常吞掉 | 0 | 每处 catch 都有 LogError/LogWarning |
| TODO/FIXME | 0 | 零遗留 |

## 四、注释质量

**10+ 处包含真实生产 Bug 回溯**：

- `AlertEvaluationService.cs`: 震荡指标导致告警丢失的修复
- `authStore.ts`: 页面刷新时路由 race condition 的修复
- `useSignalR.ts`: 重连后 handler N+1 次触发的修复
- `useTokenRefresh.ts`: 绝对时间戳替代相对计时的修复
- `LocalBuffer.cs`: 溢出数据先存 SQLite 再丢弃的修复
- `AuditActionFilter.cs`: 创建操作审计 resourceId 缺失的修复
- `TimescaleDbSetup.cs`: 全局保留期设最大套餐而非最小值的修复
