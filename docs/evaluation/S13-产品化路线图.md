S12-90天行动方案 回答的是 **"怎么找到第一个付钱的人"**。

两者的根本区别：

| | S12（验证 sprint） | S13（产品化路线图） |
|------|------------------|------------------|

## 一、核心理念：什么才算"产品"

你的代码仓库有 23 万行，但它还不是一个产品。**产品 = 客户愿意持续付钱使用的系统。** 中间的差距不在代码量，而在以下五件事：

```
技术项目 → 产品化差距
┌────────────────────────────────────┐
│  代码项目          │  产品           │
├────────────────────────────────────┤
│  你自己能跑起来      │  客户能自己部署    │
│  你知道怎么用       │  有文档和引导     │
│  功能完整           │  只解决一个痛点   │
│  技术选型漂亮       │  容错和恢复可靠   │
│  你一个人能维护      │  有新客户时能交付  │
└────────────────────────────────────┘
```

**产品化的核心矛盾：**
- 你想加功能（代码惯性）
- 市场需要你专注（商业惯性）
- 你的资源只够做一件事

> 解决矛盾的方法只有一个：**以"能否帮助获取/留住下一个客户"为标准，筛选每一个需求。**

## 二、功能优先矩阵：P0-P3

以下列表以"对获取/留住客户的影响"为唯一标准，**不是技术优雅度或代码整洁度**。

### P0 — 不修，客户不会买（或留不住）

| 项目 | 原因 | 工作量估计 | 触发阶段 |
|------|------|-----------|---------|
| MQTT TLS 加密 | 工厂安全审计一票否决 | 2 天 | 第 1 周 |
| 安装脚本一键部署（docker compose + 初始化） | 客户（或客户的 IT）必须在 30 分钟内跑起来 | 3 天 | 第 1 周 |
| ~~内置演示模式（预设 10 台模拟设备，有数据有告警有工单）~~ | 客户要 demo，不能只给空页面看 | ✅ 已完成（`SEED_DEMO_DATA=full`，仅隔离授权环境；固定 ID、24 小时遥测、告警、工单，可重复启动） | 第 2 周 |
| 邮件/钉钉/飞书告警通知 | 工单告警必须有推送，没人天天看网页 | 5 天 | 第 2 周 |
| ~~基础安装文档（PDF 格式，不是 README）~~ | 客户需要能打印出来照着做的说明书 | ✅ 已完成（`docs/INSTALLATION_GUIDE.md` + `output/pdf/equipsense-production-installation-guide.pdf`，源文档可复现生成） | 第 3 周 |

### P1 — 修了会显著提升转化率

| 项目 | 原因 | 工作量估计 | 触发阶段 |
|------|------|-----------|---------|
| InMemoryEventBus 扩容（1000→10000） | demo 时压力一大丢告警太尴尬 | 1 天 | 第 1 周 |
| Web 界面设备注册流程简化（减少表单字段） | 客户首次使用体验 | 2 天 | 第 3 周 |
| 告警阈值预设（按常见设备类型给出推荐值） | 空白的告警规则 → 客户不知道填什么 | 2 天 | 第 4 周 |
| 工单状态页面增加"扫码查看"二维码 | 车间工人不用登录系统 | 1 天 | 第 6 周 |
| 数据导出 CSV（告警历史、设备趋势） | 很多低点用户要导出给领导看 | 1 天 | 第 6 周 |
| 实时大屏模式（全屏、深色、大字） | 车间现场屏幕展示，老板喜欢 | 3 天 | 第 8 周 |

### P2 — 有更好，但不影响初期转化

| 项目 | 原因 | 时机 |
|------|------|------|
| OPC UA 适配器 I/O 线程模型优化 | 客户只有几台设备，压力不大 | 有第一个客户后 |
| SignalR 重连防抖优化 | 目前已经够用 | 用户抱怨断连时 |
| NuGet CVE 修复 | 安全审计只在正式采购时触发 | 客户进入采购流程前 |
| AI 四级降级调参 | demo 阶段用默认参数够了 | 客户反馈"误报太多"时 |
| Edge Gateway SQLite 7 天缓存 | 初期客户没有网络不稳定的情况 | 试用客户反馈断网时 |
| 知识库审核流 UI 优化 | 初期客户不依赖 AI 规则 | 知识库用户增长时 |

### P3 — 两年内不需要碰（客户没提就不要做）

| 项目 | 原因 |
|------|------|
| 分布式锁/水平扩容 | 单实例扛 100 台设备足够，初期客户可能不到 10 台 |
| RabbitMQ 替换 EventBus | 同上，多实例需求不存在 |
| 微服务拆分 | 模块化单体在 50 台设备以内完全够用 |
| OAuth 2.0 BCP / 高级 MFA | 初期不涉及企业 SSO 集成 |
| 自动化压测集成到 CI | 初期不需要 |
| PWA 离线模式完善 | 客户全部在 WIFI/4G 环境下使用 |

### 优先矩阵决策树

```
这个功能要不要做？
├── 客户直接说需要？ → P0 或 P1
├── 客户没说，但缺了就留不住？ → P0
├── 客户没说，但有显著提升转化率？ → P1
├── 技术债，但目前不影响客户？ → P2
├── 自己觉得"应该要"但客户没提？ → P3 ❌ 不要做
└── 纯粹是觉得"代码不够优雅"？ → P3 ❌ 绝对不要做
```

## 三、目标客户画像（ICP）

### 3.1 第一阶段（前 3 个月）：超级聚焦

```
┌─────────────────────────────────────┐
│  理想客户画像                        │
├─────────────────────────────────────┤
│  场景: 小型离散制造工厂                │
│  人数: 50-200 人                     │
│  关键设备: 注塑机 / CNC / 冲压 / 空压机 │
│  设备数量: 5-20 台                    │
│  决策者: 老板本人或设备主管             │
│  痛点: "设备突然停了没人知道"           │
│  IT 能力: 无专职 IT，可能有个管电脑的   │
│  预算: ¥1,000-3,000/月               │
│  签单周期: 1-4 周                     │
└─────────────────────────────────────┘
```

**为什么要这么聚焦？**
- 你的资源只够服务一种客户
- 同样的安装流程、同样的告警配置、同样的话术 → 可复制
- 注塑机/CNC 是离散制造最有代表性的通用设备
- 小型工厂决策快：老板就是厂长，说了就签

### 3.2 第二阶段（3-12 个月）：横向扩展

当你在某个设备场景（如注塑机）有 3-5 个成功案例后：

```
扩展路径 1: 同一设备类型，不同行业
  注塑机 → 家电配件厂 → 汽车零部件厂 → 玩具厂
  (设备一样，痛点一样，话术微调)

扩展路径 2: 同一行业，更多设备类型
  注塑机 + 空压机 + 冷却塔 → 同一个工厂更多设备
  (客户相同，扩展 ARPU 值)

扩展路径 3: 区域性复制
  东莞长安 3 家 → 东莞厚街 5 家 → 深圳宝安 5 家
  (地理集中，安装和服务成本低)
```

### 3.3 不要碰的客户

| 不要碰 | 原因 |
|--------|------|
| 大型集团公司（正泰、富士康级别） | 决策周期 12-18 个月，合规要求几百份 |
| 流程工业（石化、化工、制药） | 设备复杂、安全要求极高、责任巨大 |
| 半导体/精密制造 | 精度要求到纳米级，异常检测门槛太高 |
| 客户没有专职设备管理员 | 没人使用你的系统，装了就吃灰 |
| 客户已有成熟 IoT 平台 | 替换成本太高，你没有议价能力 |

## 五、开源策略

### 5.1 什么是正确的开源策略？

对于独立开发者，"开源"不是意识形态选择，而是**获客策略**。

| 开源的目的 | 不是 | 是 |
|-----------|------|----|
| ❌ 为了"做贡献" | 为了扩大影响力 | ✅ |
| ❌ 为了社区荣誉 | 为了让别人发现你的产品 | ✅ |
| ❌ 把所有代码都放出去 | 只开源非核心部分 | ✅ |

### 5.2 推荐的开源布局

```
公开（全开源）:
  - Edge Gateway（边缘网关，让别人免费使用并帮你传播）
  - 协议适配器 SDK（Modbus/OPC UA 示例）
  - 前端组件库（部分通用组件）
  - 模拟器（方便别人体验）

闭源（保留在付费产品中）:
  - AI 分析引擎和规则引擎（核心算法）
  - 告警引擎（聚合防风暴等独有逻辑）
  - 工单工作流引擎（业务流程）
  - 后端完整代码（这不是 SaaS 代码，没人能直接拿去用）

有条件公开（只对试用客户）:
  - 安装脚本和 Docker Compose
  - 配置文档
  - API 文档
```

### 5.3 GitHub 运营计划

```
第 1 步-初始化（第 1 周）:
  - 完善 README（架构图、截图、5 分钟快速开始）
  - 加 CONTRIBUTING.md、LICENSE（AGPL v3）
  - 加 GitHub Actions CI badge

第 2 步-内容发布（第 2-4 周）:
  - 在 /r/dotnet、/r/industrial_iot 发 Show HN 风格帖子
  - 在知乎/掘金发深度文章，末尾附 GitHub 链接

第 3 步-社区运营（持续）:
  - 回复 issue 和 discussion（体现活跃度）
  - 在 GitHub 相关项目 issue 里友善留链接
  - 目标是：别人在 GitHub 搜索 "IIoT" ".NET iot" 时能看到你
```

## 七、兼职投入估算

你的假设：**独立开发，无资金无人脉** → 意味着你需要一份收入来源。以下按"每天下班后 + 周末"计算。

| 阶段 | 每周投入 | 工作内容 | 可否兼职？ |
|------|---------|---------|-----------|
| 第 0-2 周：产品准备 | 15-20h | P0 修复 + 演示环境 + 销售材料 | ✅ 完全可以 |
| 第 3-6 周：获客启动 | 10-15h + 周末 1 天 | 内容写作 + 展会/扫街 | ✅ 可以，周末集中跑 |
| 第 7-12 周：试用跟进 | 5-10h | 客户安装 + 反馈 + 迭代 | ✅ 可以，主要是远程 |
| 第 13-24 周：付费转化 | 10-20h（高峰期） | 谈判 + 部署 + 优化 | ⚠️ 可能需请假 |
| 第 25 周+：全职决策 | 20h+ | 取决于客户数量 | ⚠️ 开始吃力 |

**关键判断节点：**
- 第 12 周：如果有 ≥1 个付费客户 → 考虑是否辞职
- 如果 0 个付费客户但 ≥3 个活跃试用的 → 再坚持 90 天
- 如果 0 个试用 → 考虑 pivot 或停掉商业化转为作品集

## 八、产品化的非技术事项清单

很多独立开发者只关注代码，忽略了产品化的"脏活"。以下是必须处理的非技术事项：

### 8.1 法律与合规

| 事项 | 时间 | 成本 |
|------|------|------|
| 注册个体户（可开票、签合同） | 3-5 个工作日 | ¥500 左右 |
| 产品隐私声明（收集哪些设备数据、怎么存） | 1 天 | 可以自己写 |
| 数据安全承诺（不上传客户工艺参数） | 1 天 | 这是客户最关心的 |
| 简单的 SaaS 服务条款（非签约客户免费、无 SLA） | 半天 | 参考同类产品改写 |

### 8.2 定价与收费

```
定价三原则:
  1. 便宜到小老板不用犹豫（¥1,000-3,000/月）
  2. 简单到一句话说清楚（不按设备数、不按数据量，按月固定价）
  3. 第一个客户可以打折（但不要免费超过 3 个月）

推荐定价:
  Starter   ¥1,500/月  — 10 台设备，1 个用户
  Standard  ¥3,000/月  — 30 台设备，3 个用户
  Premium   ¥8,000/月  — 100 台设备，10 个用户

  首年特价: Starter ¥1,000/月，Standard ¥2,000/月
  年度预付: 送 2 个月（相当于打 83 折）

  对第一个客户: ¥1,000/月 也可以签！
  目的是拿到"有人付钱"的证据，不是最大化首单收入

后续提价策略: 每 6 个月涨 15-20%，对老客户保持原价 12 个月
```

### 8.3 实施流程标准化

一旦有 3 个客户以上，必须标准化实施流程：

```
标准实施 SOP:
  第 1 天: 客户签合同 → 你发安装文档 + demo 链接
  第 2-3 天: 客户部署（你远程支持 1 小时）
  第 4-7 天: 确认数据接入正常，调告警阈值
  第 8-14 天: 观察期，记录告警质量
  第 15 天: 约电话——"有什么发现？"
  第 30 天: 试用结束，谈续费
```

**目标是：** 一套流程可复制，不需要你每次都 "重新发明轮子"。

## 十、心理准备：独立创业者最常犯的 5 个错误

| 错误 | 表现 | 后果 | 怎么避免 |
|------|------|------|---------|
| **功能蔓延** | "再加一个功能客户就会来了" | 写了一大堆客户用不上的功能 | 每个新功能必须经过"客户是否直接要求"检验 |
| **完美主义** | "等我把这个 Bug 修完再去找客户" | 永远找不到第一个客户 | 现在就去，修最少的 Bug 去接触客户 |
| **廉价化** | "我免费给客户用" | 客户不珍惜，也不给反馈 | 免费要有条件（帮介绍、给反馈、写案例） |
| **大客户幻觉** | "只要搞定一个上市企业就够了" | 浪费 6-12 个月在永远签不下来的客户上 | 只做决策周期 ≤4 周的客户 |
| **一个人干** | "我自己能写代码、能销售、能实施" | 哪样都做不精 | 兼职阶段钱花在"买工具省时间"，全职阶段第一个招销售 |
