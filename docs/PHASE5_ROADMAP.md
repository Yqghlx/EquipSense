# EquipSense Phase 5 规划：从"响应性维护"到"预测性维护"

> 版本：v1.0
> 日期：2026-06-14
> 前置条件：Phase 1-4 已完成（28 次提交，637+293 单测，8 条链路验证）

---

## 一、Phase 5 定位

**核心目标**：在 Phase 1-4"响应性维护"基础上，升级为真正的"预测性维护"平台。

**与 Phase 1-4 的关系**：
- ✅ **不否定**已有设计（LLM 根因、评估仪表盘、四级降级全部保留）
- ✅ **升级**部分功能（知识库→FMEA、异常检测→RUL 预测）
- ✅ **新增**竞品标配功能（数字孪生、低代码、报表引擎）

**竞品参照**：
- Uptake：ML 模型为核心（RUL 预测）
- PTC ThingWorx：数字孪生 3D 可视化
- IBM Maximo：FMEA 故障模式库
- 涂鸦工业：低代码配置 + 快速部署

---

## 二、Phase 5 功能清单（按优先级排序）

### P0：预测性维护核心能力

#### 2.1 FMEA 故障模式库升级

**目标**：将现有"知识规则"升级为行业标准的 FMEA（故障模式与影响分析）库。

**竞品参照**：
- IBM Maximo：故障代码库（ISO 14224 标准）
- 树根互联：故障模式库

**与现有系统的衔接**：
- 现有 `knowledge_rules` 表保留，新增 `fmea_library` 表
- 规则引擎从"IF 条件 THEN 结论"升级为"故障模式 + 影响 + 检测方式 + 建议措施"
- 前端知识库页面增加 FMEA 视图

**数据结构示例**：
```json
{
  "failureMode": "电机过载",
  "cause": "轴承磨损 / 负载过大 / 冷却失效",
  "effect": "设备停机 / 生产效率下降",
  "detection": "电流 > 180A 持续 5 分钟",
  "recommendedAction": "检查轴承温度 / 减小负载 / 清理冷却系统",
  "severity": 9,
  "occurrence": 6,
  "detectability": 4,
  "rpn": 216
}
```

**预计工作量**：2-3 周

---

#### 2.2 RUL 剩余使用寿命预测

**目标**：将 ML.NET 从"异常检测（SrCnn）"升级为"剩余寿命预测"。

**竞品参照**：
- Uptake：ML 模型预测故障时间窗口
- MindSphere Predictive：寿命预测 + 维护建议

**与现有系统的衔接**：
- 现有 `MlAnomalyDetectionService` 保留（异常检测仍有价值）
- 新增 `RulPredictionService`（剩余寿命预测）
- 训练数据：历史遥测 + 故障记录 + 维修日志
- 输出：剩余天数 + 置信度 + 建议维护时间

**技术路线**：
1. 数据准备：清洗历史数据，标注故障时间点
2. 特征工程：从遥测数据提取退化特征（趋势、方差、频域特征）
3. 模型选择：LSTM / 随机森林 / 线性退化模型
4. 部署：模型服务化，每日预测一次

**预计工作量**：4-6 周（数据准备 + 模型训练 + 部署）

**竞品参照**：

### P2：规模化与运营能力

### P3：体验优化（可选）

#### 2.7 LLM 根因诊断优化

**目标**：保留 LLM 诊断，但定位为"辅助建议"而非"诊断结论"。

**调整方向**：
- UI 提示："以下为 AI 辅助分析，仅供参考"
- 增加可解释性：显示 LLM 推理依据（引用了哪些规则/数据）
- 保留四级降级架构（L1 LLM / L2 规则 / L3 统计 / L4 ML.NET）

**工作量**：1 周（UI 调整 + 提示文案）

---

#### 2.8 评估仪表盘保留

**目标**：保留评估功能，定位为"系统自检"而非客户功能。

**调整方向**：
- 入口从侧边栏移到"系统设置 → 评估工具"
- 文档说明：用于实施团队验证 AI 模型准确性
- 不对最终用户展示

**工作量**：0.5 周（入口调整 + 文档更新）

## 六、结论

Phase 5 不是对 Phase 1-4 的否定，而是在其基础上的**自然演进**：

1. **从"响应"到"预测"**：FMEA + RUL 让系统从"故障后告警"升级为"故障前预警"
2. **从"功能"到"体验"**：3D 可视化 + 移动端让系统从"能用"升级为"好用"
3. **从"定制"到"规模"**：低代码 + 报表让系统从"项目制"升级为"产品化"

**Phase 1-4 的设计方案完全正确**，我们完成了从 0 到 1 的闭环。Phase 5 是从 1 到 10 的规模化。
