# 审批 HTTP 授权集成验证设计

## 背景

审批服务层已经显式校验租户、当前步骤角色和指定审批人，但现有控制器集成测试主要验证管理员成功路径。生产风险不只来自服务实现，也来自 JWT 声明生成、认证声明映射、租户上下文解析、权限中间件和控制器参数传递之间的组合回归。

## 目标

在真实 `WebApplicationFactory` HTTP 管道中验证审批授权边界：

1. 同租户、角色和指定审批人均匹配时，审批请求成功并正确持久化。
2. 角色不匹配时返回 `403`，审批记录和工单状态保持不变。
3. 指定审批人不匹配时返回 `403`，审批记录和工单状态保持不变。
4. 待审批列表只返回当前租户、当前角色且指定给当前用户或未指定用户的记录。
5. 另一租户的审批记录不能通过 HTTP 请求被读取或修改，资源不可见统一返回 `404`，而同租户已结束审批仍返回业务冲突 `409`。
6. HTTP 请求缺失角色声明时由权限中间件返回 `403`；服务层直接调用缺失角色时仍返回空列表。

## 方案

新增独立的 `ApprovalAuthorizationIntegrationTests`，使用现有 `CustomWebApplicationFactory`、SQLite 集成数据库和生产同源 `JwtTokenService` 生成 JWT。测试直接向测试数据库写入最小工单及审批记录，避免依赖异步事件或 UI 流程；HTTP 请求仍完整经过认证、租户解析、权限中间件、控制器、应用服务和 EF Core。

测试 JWT 使用 `sub`、`tenant_id`、`role` 等生产同名声明，不伪造服务或中间件。数据库断言同时检查 `WorkOrderApproval.Action`、`ApproverId`、`Comment`、`ActedAt` 以及 `WorkOrder.Status`，确保越权失败没有隐藏副作用。

## 非目标

- 不改变审批服务的授权规则或角色矩阵；只有红灯明确证明 HTTP 管道存在缺陷时才修改生产代码。
- 不把 SQLite 集成测试当作 PostgreSQL 迁移验证；PostgreSQL 迁移继续由现有生产 runtime smoke 覆盖。
- 不新增前端页面或改变审批 API 响应格式。

## 验收标准

- 新增集成测试全部通过，且删除或绕过对应授权检查时能稳定失败。
- 全量集成测试、后端单元测试和 Release 构建通过。
- 测试报告与风险登记补充“服务层 + HTTP 集成层”两层审批授权证据。
