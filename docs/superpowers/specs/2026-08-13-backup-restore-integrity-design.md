# 备份批次完整性与恢复前门禁设计

## 背景

项目现有 `backup.sh` 已分别校验 PostgreSQL、附件和 Redis 归档，`restore.sh` 也支持
恢复前 dry-run 与真实隔离演练。但三个文件仍主要依赖运维人员从文件名手工选择同一批次：
脚本没有一份把文件、大小和内容摘要绑定在一起的批次证据，因此误选不同时间点的数据库和
附件，或在备份落盘后文件被篡改，可能直到恢复中途或恢复后才被发现。

## 目标

1. 每次完整备份成功时生成一个只包含相对文件名、文件大小和 SHA-256 的批次清单。
2. 清单只在本地所有启用组件备份成功且逐个校验后以原子方式写入；清单写入失败必须令整次
   备份返回非零，并且不把该批次同步到异地存储。
3. `restore.sh --confirm` 在停止服务、重建数据库或覆盖附件前验证清单、文件名、大小和摘要。
   清单校验失败时不得调用 Docker 或 AWS。
4. 保留历史无清单备份的恢复能力，但必须显式传入 `--legacy`；生产确认恢复默认拒绝无清单
   输入，避免兼容路径被误当作正常生产流程。
5. 隔离 Docker 演练和脚本行为测试证明：同批次恢复成功、串批次被拒绝、内容篡改被拒绝，
   且敏感值不出现在输出中。

## 非目标

- 不修改真实 `docker/.env`、生产数据库、对象存储或证书。
- 不改变 PostgreSQL、附件和 Redis 的备份格式，也不删除历史 `.sql.gz` 兼容恢复能力。
- 不把备份清单当作加密或不可伪造的签名；生产环境仍需使用受控备份目录、对象存储权限和
  密钥管理系统保护备份与访问凭据。

## 设计

### 批次清单格式

清单文件命名为 `backup-manifest_<TIMESTAMP>.tsv`，使用 UTF-8 文本和固定字段，不执行为
Shell 代码：

```text
format	equipsense-backup-manifest-v1
batch_id	20260813_120000
artifact	database	equipai_20260813_120000.dump	1234	<64 位 sha256>
artifact	attachments	attachments_20260813_120000.tar.gz	5678	<64 位 sha256>
artifact	redis	redis_20260813_120000.rdb	90	<64 位 sha256>
```

`artifact` 行只包含实际生成的启用组件。文件名必须是备份目录下的单层安全文件名；恢复时
传入文件的 basename、字节数和 SHA-256 必须与清单对应行完全一致。清单本身以临时文件写入
后 `mv`，保证读取方不会看到半份清单。

### 备份流程

1. 保持现有单实例锁和各组件完整性校验。
2. 所有启用组件完成后，为当前批次文件计算 SHA-256 和大小。
3. 写入并校验清单；失败则删除清单、标记备份失败，并跳过 S3 同步。
4. 清理策略同时清理过期清单；异地同步纳入 `backup-manifest_*.tsv`。

### 恢复流程

1. 解析 `--manifest`，只读取固定 TSV 字段，不 `source` 文件。
2. 在 `--confirm` 获取恢复锁和调用 Docker 之前，验证清单版本、批次、文件名、大小和摘要。
3. `--skip-attachments` 允许清单包含附件但不恢复；未跳过时必须存在并验证附件条目。
4. 没有清单时，dry-run 可继续展示兼容计划；确认恢复必须显式提供 `--legacy`，并在输出中
   标明这是无批次完整性证据的历史路径。

### 错误处理与兼容性

- 任何清单语法、路径、大小或摘要错误都在恢复前返回非零，不输出凭据或完整文件内容。
- `--manifest` 不匹配传入的数据库/附件/Redis 文件时拒绝恢复，防止跨批次拼接。
- 现有没有清单的测试夹具和历史 `.sql.gz` 仍通过 `--legacy` 覆盖；新隔离演练默认使用清单。

## 验收标准

- `bash tests/scripts/production-scripts-test.sh` 通过，并包含清单生成、串批次拒绝、篡改拒绝、
  无清单确认恢复需要 `--legacy` 和 Docker 未被调用的断言。
- `bash tests/backup-restore-rehearsal.sh` 在 Docker 可用环境中通过，且恢复使用同批次清单。
- `bash -n docker/backup.sh docker/restore.sh tests/backup-restore-rehearsal.sh` 通过。
- `docs/OPS_RUNBOOK.md` 明确记录清单选择、SHA-256 校验、兼容模式边界和人工演练要求。
