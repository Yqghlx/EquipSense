# 用户 PII 应用层加密设计

## 背景与目标

当前 `users.email` 和 `users.phone` 由 EF Core 直接以明文写入 PostgreSQL。数据库层 TDE 可以保护磁盘介质，但无法防止拥有表读取权限的账户直接看到邮箱和手机号，也无法满足应用层敏感字段保护的生产要求。

本设计只处理用户联系方式这两个 PII 字段，目标是：

1. 数据库中不再保存邮箱和手机号明文。
2. 登录、密码重置和用户信息更新仍保持现有 API 行为与用户体验。
3. 等值查找不依赖解密后全表扫描。
4. 历史数据库能够在首次升级时自动、安全、可重试地迁移。
5. 密钥缺失、密文损坏或历史数据迁移失败时 fail-closed，不让服务带着不一致数据启动。

## 方案选择

### 采用：AES-256-GCM 密文 + 字段级 HMAC-SHA256 盲索引

- 邮箱和手机号仍使用现有 `email` / `phone` 列，但列值由 `enc:v1:<nonce>.<tag>.<ciphertext>` 组成。
- `email_lookup_hash` 和 `phone_lookup_hash` 保存规范化值的 HMAC-SHA256 十六进制摘要，并建立普通索引。
- 加密每次使用新的随机 96-bit nonce，因此相同联系方式不会产生相同密文。
- 加密和盲索引使用同一个外部 32 字节主密钥，通过不同的域分隔标签派生独立子密钥，避免密钥复用。

不采用确定性加密，因为相同邮箱会暴露频率和关联关系；不采用仅哈希，因为应用仍需要将邮箱交给 SMTP 服务发送邮件。

## 数据流

### 写入

1. API 请求进入应用层，邮箱先执行 trim + 小写规范化，手机号执行 trim、删除空格、短横线和括号。
2. EF Core 将实体中的业务明文通过 ValueConverter 转换为 AES-GCM 密文。
3. `AppDbContext.SaveChanges` 在保存新增或修改的用户时计算对应盲索引；联系方式被清空时同步清空盲索引。
4. 数据库仅接收密文和 HMAC 摘要。

### 读取

1. EF Core 从数据库读取密文并通过 ValueConverter 解密为内存中的业务明文。
2. DTO 映射和邮件发送继续使用原有 `User.Email` / `User.Phone` 属性。
3. 任何解密异常都直接失败，不返回密文或静默当作空值。

### 查找

- 登录和密码重置先规范化输入并计算盲索引，再使用 `email_lookup_hash` 查询。
- 不再对 `u.Email == input` 生成 SQL，避免随机密文无法等值匹配，也避免全表扫描。
- 盲索引不用于向 API 返回数据，且不写入日志。

## 密钥与配置

- 配置键：`Security:PiiEncryptionKey`；Docker 环境变量：`PII_ENCRYPTION_KEY`。
- 必须是 Base64 编码的 32 字节密钥。
- Production 缺失、格式错误或长度不正确时，启动校验失败。
- Development/Testing 在未配置时使用代码内固定的开发专用后备密钥，仅用于本地可重复启动；生产配置门禁仍强制真实密钥。
- 密钥丢失将导致联系方式无法解密，因此必须与数据库备份分离保存，并纳入密钥管理系统备份和轮换流程。

## 历史数据迁移

新增 `email_lookup_hash` / `phone_lookup_hash` 两列及索引。数据库迁移完成后，在既有数据库初始化会话锁内执行一次参数化原子批处理：

1. 通过原始数据库命令读取旧列值，绕过 ValueConverter，避免旧明文被当作密文解码。
2. 对未带 `enc:v1:` 前缀的值计算密文和盲索引，并更新同一行。
3. 已加密但盲索引为空的行只补充盲索引，保证重复启动幂等。
4. 在同一数据库事务中处理全部行，只有最终一致性检查通过后才一次提交；单行失败立即回滚整批并阻止应用继续启动，不清空原值。
5. 迁移完成后通过计数查询确认仍存在的非密文值为零。

新建数据库不需要回填；种子用户由 ValueConverter 直接加密写入。

## 错误处理与安全边界

- 密文格式、Base64、nonce、tag 或认证校验失败时抛出 `CryptographicException`。
- 生产环境禁止将未加密值作为兼容路径返回；迁移器负责处理历史值。
- 不在日志中输出邮箱、手机号、密钥、密文或盲索引。
- 盲索引使用恒时比较只用于验证测试和轮换工具；数据库查询使用摘要等值匹配。
- 该设计不提供模糊搜索。用户列表关键词搜索仍只搜索用户名和显示名称，避免扩大 PII 泄露面。

## 测试与验收

- 保护器单测：随机密文、往返解密、不同字段域隔离、篡改拒绝、格式拒绝、规范化一致性、开发后备密钥和生产配置门禁。
- DbContext 单测：新增/修改/清空邮箱手机号时盲索引同步；数据库存储值不是明文。
- AuthService 单测：登录和密码重置通过盲索引查找，原有明文输入仍可用。
- 历史迁移单测：明文回填、已加密补索引、重复执行幂等、失败不清空原值。
- PostgreSQL 集成测试：迁移后真实数据库列值为密文，盲索引可命中，应用读取可解密。
- Production runtime smoke：注入随机 `PII_ENCRYPTION_KEY`，覆盖迁移、种子登录和现有全量 E2E。

## 范围外事项

- 不改变用户名、显示名称、审计日志历史文本或外部集成配置中的联系方式。
- 不在本次设计内实现密钥在线轮换；轮换需单独设计“新旧密钥并存 + 批量重加密 + 回滚”流程。
- 不改变真实生产环境中的凭据和证书文件。
