# 生产环境本地密钥初始化设计

## 背景

生产部署必须使用相互独立的强凭据，但逐项手工修改 `docker/.env` 容易遗漏字段、复用密码或把占位值带入部署。现有 `docker/setup.sh` 已经是 fail-closed 门禁，不能为了“方便启动”自动生成证书、许可证或租户配置。

## 目标

提供一个显式调用的初始化脚本，安全生成可以由本机随机源产生的生产凭据，并把剩余的供应商/部署专属配置交给现有校验器继续拦截。

## 非目标

- 不生成或替换 TLS、MQTT 证书和私钥。
- 不生成 AutoMapper 供应商许可证、真实租户 UUID、生产域名或 CORS 地址。
- 不覆盖任何已有的非占位凭据，不提供强制覆盖/轮换参数。
- 不改变 `setup.sh` 的默认行为：占位配置仍然失败，生产证书仍必须预置。

## 方案

新增 `docker/bootstrap-production-secrets.sh`，默认操作同目录的 `.env`，也支持 `--env-file` 指定文件。脚本只处理已存在或必填的本地随机字段：数据库、Redis、RabbitMQ、MQTT、五个种子账户、JWT、TOTP、PII、网关、Seq 和 Grafana 凭据；可选的 `AUTH_MACHINE_API_KEY` 仅在配置行已启用且仍为占位值时生成。

脚本先检查输入文件存在、不是符号链接、没有重复键，并使用目录锁避免并发更新。生成值只在进程内存和权限为 `600` 的临时文件中流转，不写入日志、不作为子进程参数传递。更新完成后用同目录 `mv` 原子替换原文件；任一生成或写入失败都保留原文件不变。

生成完成后脚本调用同目录的 `validate-env.sh`。若许可证、域名、租户、证书或其它门禁仍未满足，脚本仍以非零退出，但会保留已经安全生成的本地凭据并明确列出下一步需要人工配置的变量名。这样既减少手工错误，也不会让“部分初始化”被误认为可发布。

## 验收标准

1. 占位 `.env` 能生成独立的强随机本地凭据，且日志不包含任何生成值。
2. 已有有效凭据保持原值；重复键、符号链接和并发锁会在写入前失败，原文件不变。
3. 生成后的文件权限为 `600`，更新使用临时文件原子替换。
4. 供应商许可证、租户 UUID、生产域名和证书不会被生成；现有生产校验器继续返回非零。
5. 现有生产脚本测试、Shell 语法检查、后端/前端和 Production smoke 不回归。
