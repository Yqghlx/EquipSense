# 审计日志导出失败反馈设计

## 背景

`frontend/src/pages/AuditLogsPage.tsx` 的 CSV 导出调用在失败时直接吞掉异常。用户看不到失败原因，也无法确认是否需要重试；这会把网络故障或权限失败误认为导出成功。

## 目标

- 导出失败时显示中英文一致、不会泄露后端内部细节的错误提示。
- 导出请求进行中禁用按钮，避免用户重复点击造成重复请求。
- 保持现有筛选参数、下载行为和成功路径不变。
- 通过页面行为测试证明失败提示和按钮恢复逻辑。

## 非目标

- 不修改后端导出 API、CSV 内容或权限逻辑。
- 不把原始服务器异常文本直接展示给用户。
- 不引入全局 API 错误处理，避免改变其他页面的错误呈现行为。

## 方案决策

采用页面局部状态 + Sonner Toast：

1. `isExporting` 控制导出按钮的禁用和加载文案/图标。
2. `try/catch/finally` 保证失败提示出现，且无论成功或失败都恢复按钮。
3. 失败提示使用新的 `audit.exportFailed` i18n 键；成功时不增加额外 Toast，避免下载动作产生重复反馈。

这种方案改动范围最小，沿用页面已有的 `sonner` 依赖，不会改变全局请求错误策略。

## 验收标准

- 导出 Promise 拒绝时调用本地化错误 Toast。
- 导出 Promise 未完成时按钮不可再次点击，并展示导出中状态。
- Promise 完成或拒绝后按钮恢复可用。
- 中英文资源键完全对齐。
- 现有审计日志加载、筛选和成功导出测试继续通过。
