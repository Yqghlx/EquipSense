# 生产演示数据播种策略设计

## 背景

当前 `DataSeeder` 在 Production 启动时也会创建第二个测试租户和 `AC-001` 示例空压机。这样会让真实生产库出现验收专用数据，并可能让运营人员误以为设备已经接入。隔离 Production smoke 又确实需要这些数据来验证完整链路，因此不能简单删除种子逻辑。

## 设计

新增 `SEED_DEMO_DATA` 作为演示/验收业务数据的显式开关：

- 非 Production 环境保持现有行为，默认播种开发演示数据。
- Production 环境只有在 `SEED_DEMO_DATA=true` 或 `1` 时播种演示数据；缺失、`false`、`0` 或无法识别的值均关闭。
- 第二租户实体与 `AC-001` 示例设备只在该开关开启时创建。
- 系统租户、默认引导租户、生产种子账户、行业模板、通用默认告警规则、知识库和 FMEA 仍照常初始化；这些是应用可用性所需的基础数据，不属于演示设备数据。
- 已存在的历史演示数据不自动删除，避免启动过程产生不可逆数据变更；部署文档说明升级后需要人工审计/清理。

隔离 Production smoke 同时注入 `SEED_DEMO_DATA=true`，生产 Compose 默认注入 `false`。部署校验器在普通 Production 环境拒绝显式开启该开关，只有已有的 `--allow-isolated-e2e` 隔离授权可通过。

## 错误处理与安全边界

- 生产环境对未知开关值 fail-closed，不因拼写错误意外创建演示数据。
- Compose 和烟测契约测试锁定默认值及显式隔离覆盖，防止后续重构丢失安全默认值。
- 日志只记录是否跳过演示数据，不输出任何凭据。

## 验证

- 单元测试覆盖 Production 缺省/关闭/开启/非法值和非 Production 默认开启。
- 生产脚本测试覆盖校验器拒绝普通 Production 演示开关、隔离授权允许、Compose 默认关闭和 smoke 显式开启。
- 运行后端相关单元测试、脚本回归、构建与 diff 检查。
