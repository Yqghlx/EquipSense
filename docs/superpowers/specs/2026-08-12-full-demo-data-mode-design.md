# 完整演示数据模式设计

## 背景

产品化路线将“内置演示模式”列为 P0，要求首次部署后能看到设备、趋势、告警和工单，而不是空页面。当前 \`SEED_DEMO_DATA=true\` 只创建一个 \`AC-001\` 示例设备，不能覆盖完整产品体验；同时，真实 Production 不能因为误配而出现假设备和假工单。

## 目标

- 新增显式 \`SEED_DEMO_DATA=full\` 模式。
- 在隔离环境中创建固定的 10 台演示设备、24 小时遥测、5 条告警、4 条工单及工单日志。
- 重复启动或重复执行播种器不重复追加业务数据。
- 普通 Production 保持 \`SEED_DEMO_DATA=false\`；\`true/1\` 只保留现有最小验收种子。
- Production 下 \`full\` 必须同时设置 \`EQUIPAI_ISOLATED_E2E=true\`，否则应用启动失败。
- 现有 \`AC-001\` 固定 ID 和模拟器行为继续兼容。

## 非目标

- 不在真实租户创建完整演示数据。
- 不添加演示数据删除 API。
- 不把演示遥测接入 MQTT、告警事件总线或外部通知渠道。
- 不创建新的数据库表或迁移。
- 不把演示用户凭据写入数据库；继续使用现有隔离种子账户策略。

## 配置契约

| \`SEED_DEMO_DATA\` | 行为 |
|---|---|
| 缺失、\`false\`、\`0\` | Production 不播种演示数据；非 Production 保持最小兼容种子 |
| \`true\`、\`1\` | 最小演示种子：现有测试租户、账户和 \`AC-001\` |
| \`full\` | 最小种子 + 完整固定演示数据；Production 只允许隔离授权 |

脚本和应用两层都执行门禁。脚本层拒绝普通 Production 的 \`full\`；应用层在 Production 检测到 \`full\` 且没有 \`EQUIPAI_ISOLATED_E2E=true\` 时抛出配置异常，避免直接调用 \`docker compose\` 绕过安全边界。

## 数据集

完整数据只归属默认演示租户 \`11111111-1111-1111-1111-111111111111\`：

- 设备：保留 \`AC-001\`，补充 \`DEMO-002\` 至 \`DEMO-010\)，合计 10 台。
- 遥测：每台设备 24 个小时点、3 个指标，来源固定为 \`demo-seed\`。每次播种先清理该来源且属于这 10 台设备的旧点，再写入“昨天”的固定 24 小时窗口，保证跨天重复启动仍不累加。
- 告警：固定编码 \`DEMO-ALERT-001\` 至 \`DEMO-ALERT-005\)，覆盖 Active、Acknowledged、Resolved 等状态。
- 工单：固定编码 \`DEMO-WO-001\` 至 \`DEMO-WO-004\`，覆盖待派工、已派工、执行中和已关闭状态；每条工单有一条固定 Created 日志。
- ID：设备、告警、工单和日志使用固定 UUID，避免依赖随机 ID 实现幂等。

## 组件与职责

- \`DemoDataSeedingPolicy\`：解析 \`full\` 和 Production 隔离授权。
- \`FullDemoDataSeeder\`：只负责完整演示业务数据，使用 \`AppDbContext\` 和固定数据目录。
- \`DataSeeder\`：继续负责基础租户、账户、模板和知识规则；在 full 模式完成基础种子后调用完整播种器。
- \`validate-env.sh\`：把 \`full\` 纳入值校验并在普通 Production 拒绝。
- \`docker-compose.smoke.yml\`：显式使用 \`SEED_DEMO_DATA=full\`，让隔离 smoke 真正覆盖完整数据集。

## 幂等与错误处理

- 设备按固定 ID/编码查询，不存在才创建；租户设备计数只对新设备递增。
- 告警和工单按固定编码查询，不存在才创建；日志按工单 ID + Created 动作查询。
- 遥测在事务内按受控来源清理并批量插入，避免重复运行持续膨胀。
- 完整播种器在事务内执行；任意步骤失败回滚本次完整数据变更。
- 只使用参数化 SQL 写入 keyless 时序表，不输出任何凭据或敏感数据。

## 测试验收

- 单元测试覆盖 \`full\` 值识别、非 \`full\` 不进入完整模式、Production 缺少隔离授权时拒绝。
- 集成测试执行完整播种两次，断言 10 台设备、遥测、5 条告警、4 条工单、4 条日志数量稳定。
- 生产脚本测试覆盖普通 Production 拒绝 \`full\`、隔离授权允许 \`full\`、Compose/smoke 接线。
- 运行后端单元、集成测试、脚本测试和 \`git diff --check\`。
