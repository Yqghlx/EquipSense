# 设备对比页面设计

日期：2026-08-13

## 背景与目标

后端已经提供 `GET /api/v1/device-comparison`，前端也已有 `useDeviceComparison`，但当前产品没有用户可发现的页面入口。用户无法选择同类设备、查看窗口统计或识别偏离群体的设备，Phase 5 的设备对比能力因此没有形成可用闭环。

本切片的目标是提供一个面向只读运维角色的设备横向对比页面，帮助用户回答“同类设备中哪台的某项指标明显偏离群体”。页面展示时间窗口内的统计快照，不把统计结果误称为趋势预测，也不创建新的告警或工单。

## 方案选择

### 方案 A：独立设备对比页面（采用）

新增 `/device-comparison` 路由和侧边栏入口。页面提供设备类型、指标、时间窗口和 2–5 台设备选择，复用现有设备列表、告警规则列表和对比 API。优点是用户容易发现、筛选上下文完整、后续可扩展趋势图；代价是需要新增一个页面和少量 API 参数兼容。

### 方案 B：嵌入设备列表页

在设备列表页增加“对比”模式。优点是设备选择上下文自然；缺点是列表页已经包含 CRUD、导入和筛选，继续增加分析状态会放大页面复杂度，且从侧边栏无法直接发现对比能力。

### 方案 C：仅在仪表盘增加摘要卡片

展示偏离最大的设备。实现成本最低，但缺少指标、时间窗口和设备选择，无法满足定位同类设备差异的主要任务，因此只作为后续仪表盘快捷入口，不作为本切片主入口。

## 用户流程与界面

1. 用户从侧边栏进入“设备对比”。
2. 页面加载当前租户可见的设备类型；选择类型后加载该类型设备候选列表。
3. 用户可按设备编码或名称搜索候选设备，勾选 2–5 台设备。
4. 指标输入框支持自由输入，并以当前租户告警规则中的指标作为 datalist 建议；没有告警规则时仍可输入自定义指标，避免把分析能力绑定到告警配置权限或既有规则。
5. 用户选择 24 小时、72 小时、7 天或 30 天窗口后，只有在设备数为 2–5 且指标非空时才请求对比 API。
6. 结果区显示群体均值、标准差、时间窗口和设备明细表。明细包含设备名称、编码、平均值、最新值、最小值、最大值、样本数、Z-Score；`|Z-Score| > 2` 的记录显示异常标记并排在前面。设备名称缺失时回退到设备编码。
7. 点击设备行可进入对应设备详情页；不改变对比结果或发起额外遥测查询。

设备候选使用现有分页 API 的最大 100 条。候选总数超过 100 条且没有搜索词时，页面明确提示用户使用编码/名称搜索；搜索请求仍受当前租户和设备类型过滤。这样避免前端一次性拉取无界设备数据。

## 数据与接口设计

### 前端数据流

- `useDeviceTemplates()` 与 `useDevices({ page: 1, pageSize: 100 })`：合并设备模板和实际设备类型生成类型选项，避免只显示模板或只显示前 100 台设备中的类型。
- `useDevices({ page: 1, pageSize: 100, deviceType, keyword }, { enabled: Boolean(deviceType) })`：提供当前类型的候选设备。前端 hook 保留 `deviceType` 命名，但必须把它正确映射为后端设备列表需要的 `type` 查询参数；`keyword` 映射为后端 `keyword`。
- `useAlertRules({ page: 1, pageSize: 100 })`：仅用于指标建议，不作为页面可用性的硬依赖；查询失败时保留自由输入能力并显示非阻塞提示。
- `useDeviceComparison({ deviceType, metric, hours, deviceIds })`：仅在选择条件完整时启用。查询键对 `deviceIds` 去重并排序，避免同一选择顺序产生重复缓存。

### 现有 API 的向后兼容扩展

保留 `GET /api/v1/device-comparison?deviceType=...&metric=...&hours=...` 的既有行为：不传 `deviceIds` 时继续对比该租户该类型的所有设备。新增可选的重复查询参数：

```text
GET /api/v1/device-comparison
  ?deviceType=电机
  &metric=temperature
  &hours=168
  &deviceIds=<uuid-1>
  &deviceIds=<uuid-2>
```

服务端规则：

- `deviceIds` 传入时数量必须为 2–5；控制器拒绝超出范围的请求。
- 服务查询同时限定 `tenantId`、`deviceType` 和 `deviceIds`。跨租户或跨类型 ID 不会泄露存在性，最终按可见设备数不足返回普通“设备不足”结果。
- 遥测查询只读取已筛选设备、指标和时间窗口，继续保持一次批量查询，禁止恢复逐设备 N+1 查询。
- 统计计算语义保持不变：按设备平均值计算群体均值和标准差，再计算 Z-Score；样本不足时返回现有 `message`，不生成异常结论。

## 错误、空态与权限

- 页面需要 `device:read`，与后端对比端点一致；没有权限时不发起设备、规则或对比查询，显示无权限提示。
- 设备候选加载中使用 `role="status"`；加载失败提供重试按钮，不把失败显示成“无设备”。
- 没有同类型设备、候选不足 2 台、遥测样本不足和指标不存在分别显示可操作的说明。
- 对比请求失败使用 `role="alert"` 和重试按钮；保留已有成功结果时显示错误提示并保留旧结果，不显示成功空态。
- 指标建议加载失败不阻断自由输入，但在控件附近提供非阻塞提示。
- 所有用户可见文案、表头、异常标记、时间窗口和辅助文本同步维护 `zh.json` 与 `en.json`；测试中的翻译键使用静态 `t('...')` 调用。
- 查询参数只来自用户输入和当前租户可见数据；客户端不拼接或覆盖 `tenantId`，后端继续以认证上下文隔离租户。

## 验收标准

- 只读角色可以进入页面，选择 2–5 台同类型设备并成功看到对比统计；无效权限不会发起查询。
- URL 参数只包含设备类型、指标、窗口和设备 ID，不包含客户端租户 ID；服务端测试证明跨租户设备不会进入结果。
- 不完整条件不会请求 API；设备选择顺序变化不会产生重复查询缓存。
- 加载失败、缓存结果刷新失败、无数据和样本不足均有独立可操作状态。
- 中英文界面无硬编码中文或英文泄漏，i18n 键完整对齐。
- 后端相关单测/集成测试、前端聚焦测试以及 `check:i18n`、TypeScript、ESLint、全量 Vitest、生产构建全部通过。
- 变更经过任务级审查，并在生产路线图与评估报告中准确记录，不宣称尚未交付的趋势图或通知能力。
