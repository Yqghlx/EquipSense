# EquipSense 全面 E2E 测试计划

**日期**：2026-06-05
**状态**：设计完成，待审批

---

## 1. 概述

### 1.1 目标

对 EquipSense 工业设备智能监控平台的前端进行全面的端到端测试，深度覆盖每个按钮、表单、对话框的完整验证，包括 UI 交互、业务逻辑、错误处理和边界条件。

### 1.2 测试范围

- **环境**：Docker Compose 生产环境（https://localhost:8443）
- **浏览器**：Chromium（Playwright 自动化）
- **前端页面**：16 个页面全覆盖

### 1.3 设计决策

| 维度 | 选择 | 理由 |
|------|------|------|
| 测试深度 | 完整场景验证 | 覆盖 UI + 业务 + 错误 + 边界 |
| 数据策略 | 混合三层 | 种子数据 + 动态创建 + 模拟器触发 |
| 架构方案 | 渐进式分层 | 模块清晰，可分层运行 |

## 4. 测试数据管理策略

### 4.1 种子数据层（全局共享，一次性准备）

- 系统租户 + 测试租户
- 5 种角色用户（admin / lead / tech / operator / viewer）
- 设备类型模板（电机、泵）
- 写入 `test-results/seed-data.json`，所有测试通过 helpers 读取

### 4.2 动态创建层（每个测试独立管理）

- 测试对象：设备、告警规则、工单、知识规则
- 命名规则：`E2E-{测试名}-{时间戳}`
- afterEach 自动清理匹配 `E2E-*` 的数据

### 4.3 模拟器触发层（仅实时测试使用）

- 启动 `EquipAI.Simulator` 发送遥测数据
- 可配置设备数量、发送间隔、异常率
- 每个实时测试独立启动/停止，使用独立租户避免污染

## 5. 执行策略

### 5.1 分层运行

```bash
# 快速回归（~17 分钟）
npx playwright test e2e-comprehensive/00-* e2e-comprehensive/01-* e2e-comprehensive/02-*

# 标准验证（~35 分钟）
npx playwright test e2e-comprehensive/0[0-4]-*

# 完整覆盖（~45 分钟）
npx playwright test e2e-comprehensive/
```

## 8. helpers 公共模块设计

### 8.1 auth.ts

- `loginAs(page, role)` — 按角色登录，支持 admin/lead/tech/operator/viewer
- `getToken(page)` — 通过 API 获取认证 Token
- `loginAsWithToken(page, username, password)` — 登录并返回 Token

### 8.2 api.ts

- `createTestDevice(page, prefix, type?)` — 创建测试设备，返回设备对象
- `createThresholdRule(page, name, enabled?)` — 创建阈值告警规则
- `createCompositeRule(page, name)` — 创建组合告警规则
- `createBaselineRule(page, name)` — 创建基线告警规则
- `createTestWorkOrder(page, title, type?, priority?, deviceId?, description?)` — 创建测试工单
- `createKnowledgeRule(page, name, enabled?)` — 创建知识规则
- `createPendingRule(page, options)` — 创建待审批规则
- `triggerAlertViaAPI(page, options)` — 通过 API 触发告警
- `getAlertsViaAPI(page, filter)` — 通过 API 查询告警
- `assignWorkOrder(page, woId, userId)` — 派工
- `startWorkOrder(page, woId)` — 开始执行
- 所有创建函数自动添加 `E2E-` 前缀和时间戳

### 8.3 realtime.ts

- `startSimulator(options)` — 启动 EquipAI.Simulator 进程
- `stopSimulator(process)` — 停止模拟器
- `waitForMQTTConnection(process)` — 等待 MQTT 连接建立
- `getSimulatorDevice(page, index)` — 获取模拟器创建的设备

### 8.4 seed-data.ts

- `initSeedData(page)` — 初始化种子数据
- `getSeedData()` — 读取种子数据 JSON
- `TEST_TENANT_ID` / `TEST_DEVICE_ID` — 常量

### 8.5 assertions.ts

- `captureErrors(page)` — 捕获页面 JS 错误
- `expectNoJSErrors(page)` — 断言无 JS 错误
- `expectToastVisible(page, text)` — 断言 Toast 提示显示

### 8.6 cleanup.ts

- `cleanupTestDevices(page)` — 清理 E2E- 前缀设备
- `cleanupTestWorkOrders(page)` — 清理 E2E- 前缀工单
- `cleanupAllDevices(page)` — 清理所有测试设备
- `cleanupAllWorkOrders(page)` — 清理所有测试工单

### 8.7 导航辅助

- `navigateViaSidebar(page, name)` — 通过侧边栏导航
- `gotoDeviceDetail(page, deviceId)` — 直接跳转设备详情
- `gotoWorkOrderDetail(page, woId)` — 直接跳转工单详情
- `gotoSetupStep(page, step)` — 跳转到设备设置向导指定步骤
