# 仪表盘趋势预警卡片设计

> 日期：2026-08-13  
> 范围：Phase 5 趋势预警的第一个用户入口  
> 状态：已批准，进入实现计划

## 目标

让运维人员登录仪表盘后可以直接看到“未来 7 天内可能越过告警阈值”的设备指标，并在需要处理时一键进入设备详情。现有趋势分析 API 和 hook 已经提供数据，本次补齐可发现、可操作且不误导用户的界面入口。

## 方案选择

### 方案 A：仪表盘趋势预警卡片（采用）

在现有 Dashboard 的 OEE 与统计图表之间加入独立卡片，复用 `useTrendWarnings`。卡片只负责摘要和导航，设备详情页仍是完整遥测查看入口。

优点：改动集中、用户登录后立即可见、无需新增路由和后端查询；失败时可以在仪表盘内明确重试。缺点是设备显示名称暂时只能使用设备 ID 摘要，名称增强需要后端 DTO 或批量设备查询的后续改动。

### 方案 B：新增独立趋势分析页面

提供完整筛选、排序和历史分析页面。

优点是扩展空间大；缺点是增加路由、导航、页面状态和端到端验收成本，不能快速解决现有能力“不可发现”的问题，暂不采用。

### 方案 C：只嵌入设备详情页

在设备详情中追加单设备趋势预警。

优点是上下文完整；缺点是用户必须先知道并打开某台设备，无法发现全租户范围的即将越阈值设备，暂不采用。

## 用户界面设计

组件文件：`frontend/src/components/analysis/TrendWarningsCard.tsx`。

卡片结构：

1. 标题区显示“趋势预警”和说明“未来 7 天内可能越过阈值”；右侧显示预警数量。
2. 每条预警使用一条可聚焦的按钮式行，展示指标名、设备 ID、当前值/阈值、趋势方向和预计天数。
3. 预计 1 天内越阈值使用红色危险强调，1–3 天使用琥珀色警示，有限且超过 3 天使用蓝色信息强调；无法给出预计天数时使用中性 `noEstimate` 风险样式与文案。颜色只作为辅助，不承担唯一语义；文本同时显示天数或“暂无估算”。
4. 行点击导航到 `/devices/{deviceId}`；按钮提供包含设备和指标的可访问名称。
5. 默认最多展示 5 条，按 `daysToThreshold` 升序、缺少预计天数的记录排在后面；运行时会先过滤 `deviceId` 与 `metric` 为空字符串的非法记录，避免生成 `/devices/undefined` 之类的无效导航。当预警更多时显示剩余条数提示，但本次不新增独立趋势页或伪造不可用的“查看全部”链接。

视觉方向沿用现有 EquipSense 工业监控语言：卡片、边框、Badge 和 Tailwind 设计令牌保持一致；用左侧风险色竖线和紧凑数据排版表达“时间窗口”，不引入新的字体、图标库或全局主题。交互支持键盘焦点，尊重现有 reduced-motion 设置，不增加持续动画。

## 数据与状态

- 使用 `useTrendWarnings()`，不在前端拼接 `tenantId`；租户边界继续由后端上下文保证，并依赖现有 `authStore` 会话切换时清空 Query 缓存，避免把租户切换逻辑耦合进 hook。
- `isLoading`：显示卡片骨架或加载文案，不显示“暂无预警”。
- `isError`：始终显示明确失败提示和重试按钮，调用 hook 返回的 `refetch`；如果 TanStack Query 仍保留旧数据，错误提示下继续展示旧数据，不退化成正常空状态。
- 成功且数组为空：显示“当前没有即将越阈值的指标”，这是正常空状态。
- 成功有数据：按展示规则排序和截断；字段缺失时使用短横线，不渲染 `NaN` 或 `undefined`。
- 不改变后端响应契约，不新增 API 端点、不产生重复请求；Dashboard 挂载卡片时会增加一次已有 `useTrendWarnings` hook 请求，但不会额外重复拉取同一数据，也不将预测结果写入通知或告警表。

## 国际化与可访问性

在 `frontend/src/i18n/zh.json` 和 `frontend/src/i18n/en.json` 同步增加 `dashboard.trendWarnings.*` 键，至少包含 `oneDay`、`days`、`noEstimate`、`risk.noEstimate`、`direction.*` 和 `risk.*`。所有标题、状态、趋势方向、按钮、错误和空状态均从 i18n 获取；方向与风险键必须通过静态 `t('...')` 调用暴露给 i18n 门禁扫描，测试用英文资源验证不会泄漏中文常量。

卡片使用语义标题；重试按钮有明确文本；预警行使用按钮语义、可见焦点样式和完整 `aria-label`；风险颜色同时配合“1 天内/3 天内/暂无估算”等文字；数字格式使用统一的小数位策略。

## 测试验收

新增 `frontend/src/components/analysis/__tests__/TrendWarningsCard.test.tsx`，覆盖：

- 有预警时按预计天数排序，最多展示 5 条，并显示当前值、阈值和趋势方向；
- 点击预警行导航到对应设备详情；
- 空数组显示正常空状态；
- 任意 `isError` 都显示错误和重试按钮；有旧数据时保留旧数据，且错误时不显示正常空态；
- `daysToThreshold=null` 显示中性无估算文案，不误报为“7 天内”；
- 过滤 `deviceId` 或 `metric` 非法的运行时记录，不渲染无效导航；
- 卡片标题可通过二级 heading 查询；
- 英文翻译下不出现中文趋势文案，`1 day` / `N days` 单复数正确，关键按钮和行具有可访问名称。

扩展 `frontend/src/pages/__tests__/DashboardPage.i18n.test.tsx`，验证 Dashboard 挂载趋势预警卡片并复用英文翻译资源。保留现有 hook mock，不引入网络请求。

验收门禁：聚焦 Vitest、全量 Vitest、`npm run check:i18n`、TypeScript 检查、ESLint（`--max-warnings 1`）和生产构建全部通过。

## 非目标

- 不修改趋势线性回归、阈值选择和后端租户过滤逻辑。
- 不新增独立趋势页面、设备对比页面或通知推送规则。
- 不在本次改动中修改 API DTO 以补充设备名称；设备名称映射作为后续产品增强单独评估。
