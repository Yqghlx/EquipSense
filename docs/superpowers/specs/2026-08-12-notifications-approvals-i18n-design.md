# 通知中心与待审批页面国际化设计

## 目标

消除通知中心和待审批页面中的用户可见硬编码中文，使英文用户在告警、工单通知和审批闭环中获得一致的英文界面，同时不改变现有 API、权限、查询和操作行为。

## 范围

- `NotificationsPage`：标题、全部已读、筛选标签、空状态、表头、标记已读和查看详情提示。
- `PendingApprovalsPage`：标题、数量描述、空状态、表头、角色、状态、通过/驳回、详情提示和驳回对话框。
- `frontend/src/i18n/zh.json` 与 `frontend/src/i18n/en.json`：新增命名空间并保持键集合完全一致。
- 页面级 Vitest 回归：以英文翻译映射渲染页面，断言用户可见文本不再依赖中文硬编码。

## 设计决策

1. 翻译键按页面命名空间组织：`notifications.*` 与 `pendingApprovals.*`，避免继续扩大含义模糊的 `common`。
2. 审批角色使用稳定的角色值到翻译键的映射；未知角色保留后端原值，避免新角色上线时静默显示错误文案。
3. 通知类型过滤使用稳定的 `FilterType` 值，标签由 `t` 在渲染时生成，切换语言后无需刷新页面即可更新。
4. 数量、审批步骤和工单短 ID 使用 i18next 插值，不在组件中拼接自然语言。
5. 不重构 hooks、数据模型或 mutation 行为；本次只调整展示层和测试夹具。

## 验证标准

- 新增/更新页面测试在改造前因硬编码中文而失败。
- 改造后相关页面测试通过，现有审批行为测试继续通过。
- `npm test -- --run` 全量通过。
- `npx tsc -p tsconfig.json --noEmit`、`npm run lint`、`npm run check:i18n` 和 `npm run build` 全部通过。
