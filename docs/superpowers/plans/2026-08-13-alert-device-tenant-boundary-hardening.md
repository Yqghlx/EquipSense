# 告警设备租户边界加固实施计划

> **执行约束：**按 TDD 先写跨租户红测，再修改生产代码；每一步完成后运行聚焦测试、全量单元测试和 Release 构建。

## 目标

修复后台告警链路中绕过全局租户过滤器后仅按设备 ID/告警 ID 查询的问题，确保遥测状态更新、告警规则匹配、告警事件分发和通知展示都同时验证事件租户。

## 实施步骤

### 1. 写入失败回归测试

- `TelemetryEventHandler`：事件租户与设备租户不一致时，不更新设备状态、不调用告警评估。
- `AlertEvaluationService`：设备租户与评估租户不一致时，不使用其他租户的设备类型参与规则匹配。
- `AlertNotificationService`：事件租户与设备租户不一致时，不把其他租户的设备编码/名称写入通知内容。
- `AlertEventHandler`：事件租户与告警租户不一致时，不推送其他租户的告警编码、不创建当前租户通知。
- `AlertEvaluationService`：当前上下文租户与事件租户不同但设备属于事件租户时，仍能正常创建告警。

### 2. 最小修复

- 保留后台事件处理所需的 `IgnoreQueryFilters`，但在设备查询谓词中增加对应的 `TenantId` 条件。
- 将事件租户显式传入遥测设备状态更新方法。
- 修正文档注释，明确“绕过请求过滤器”不等于“绕过业务租户边界”。

### 3. 验证与提交

- 先运行新增红测，确认旧实现确实失败。
- 运行告警聚焦测试、全量单元测试和 Release 构建。
- 请求独立代码审查；根据审查结果修复并重复验证。
- 记录验证证据后提交 Conventional Commit。

## 验收标准

- 跨租户设备 ID 不能被遥测事件更新。
- 告警评估不能使用其他租户设备的类型信息。
- 告警事件不能按告警 ID 读取其他租户的告警编码。
- 告警通知不能泄露其他租户设备的可读标识。
- 既有后台跨租户事件处理（事件租户与设备租户一致、但无 HTTP 上下文）仍正常工作。
- 聚焦测试、全量单元测试、Release 构建和独立审查均通过。
