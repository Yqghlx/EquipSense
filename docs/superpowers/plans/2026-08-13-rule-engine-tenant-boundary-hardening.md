# 规则引擎设备租户边界加固实施计划

## 目标

确保后台根因分析的规则匹配只使用事件租户拥有的设备类型；设备 ID 与租户不匹配或设备不存在时直接返回无匹配结果。

## 实施步骤

1. 添加跨租户设备 + 同租户知识规则的红测，验证旧实现会错误返回规则。
2. 添加后台正向测试，验证当前 `ITenantContext` 不同于事件租户时，合法设备仍能匹配。
3. 在设备类型查询中增加 `TenantId` 条件，并在规则匹配前拒绝未知/跨租户设备。
4. 运行聚焦测试、全量单元测试、Release 构建，并进行独立审查后提交。

## 验收标准

- 跨租户设备不能借用设备类型匹配知识规则。
- 不存在设备不能命中通配知识规则。
- 后台合法事件不受 HTTP 租户上下文影响。
- 全量单元测试、Release 构建和独立审查通过。

## 验证记录

- 红测（旧实现）：跨租户设备测试失败，错误返回了租户 B 的规则；后台合法事件正向测试通过。
- 修复后规则引擎测试：11/11 通过。
- 全量单元测试：1565/1565 通过。
- Release 构建：0 警告、0 错误。
