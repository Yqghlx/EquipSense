# 通知偏好自助身份边界加固实施计划

## 目标

确保通知偏好读取和更新只能操作当前认证用户，避免服务被其他入口复用时通过 userId 参数读取或修改同租户其他用户的配置。

## 实施步骤

1. 为通知偏好服务注入租户上下文，补充同租户跨用户读取和更新的负向用例。
2. 在自助读取、更新路径绑定当前租户和当前用户；后台按租户筛选候选用户的分发路径保持显式租户条件。
3. 更新直接构造该服务的测试替身，并验证 SignalR 通知分发不受影响。
4. 运行全量单元测试、Release 构建和集成测试后提交。

## 验收标准

- 当前用户不能读取同租户其他用户的通知偏好。
- 当前用户不能修改同租户其他用户的通知偏好。
- 当前用户的读取、更新和 IsEnabledAsync 路径保持可用。
- 后台通知分发仍能按显式租户和候选用户筛选偏好。

## 验证记录

- 通知偏好服务测试：7/7 通过。
- SignalR 通知服务回归测试：16/16 通过。
- 全量单元测试：1589/1589 通过（Debug、Release）。
- 集成测试：177 通过、6 跳过（RabbitMQ 专项需设置 RUN_RABBITMQ_INTEGRATION_TESTS=true）。
- Release 解决方案构建：0 警告、0 错误。
- 独立代码审查：Approved，无阻断性问题。
