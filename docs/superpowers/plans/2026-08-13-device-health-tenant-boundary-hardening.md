# 设备健康度单设备租户边界加固实施计划

## 目标

修复单设备健康度计算和持久化在绕过全局租户过滤器后仅按设备 ID 查询的问题，避免设备详情接口可读取或更新其他租户设备的健康度。

## 实施步骤

1. 添加当前租户与设备租户不一致的红测，确认旧实现仍会计算/更新跨租户设备。
2. 让单设备查询显式绑定 `ITenantContext.TenantId`，并将告警、遥测质量查询使用同一租户条件。
3. 保持批量后台重算的显式 `tenantId` 路径不变，避免影响跨租户定时任务。
4. 运行聚焦测试、全量单元测试、Release 构建并进行独立审查后提交。

## 验收标准

- 当前租户不能计算或更新其他租户设备的健康度。
- 健康度使用的告警和遥测质量数据只来自同一租户。
- 批量后台重算仍能按目标租户正常工作。
- 全量单元测试、Release 构建和独立审查通过。

## 验证记录

- 跨租户单设备回归：当前租户对其他租户设备的计算与更新均返回空且不改写数据。
- 单设备健康度测试：10/10 通过。
- 后台批量重算测试：2/2 通过。
- 全量单元测试：1567/1567 通过。
- Release 构建：0 警告、0 错误。
