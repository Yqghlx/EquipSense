# 根因分析设备租户边界加固实施计划

## 目标

确保告警事件触发的根因分析和 AI 候选规则生成只使用事件租户拥有的设备信息，避免错误事件读取其他租户设备类型并写入当前租户知识候选。

## 实施步骤

1. 添加跨租户事件与设备的候选规则红测，确认旧实现会泄露其他租户设备类型。
2. 添加合法后台事件正向测试，确保事件租户设备仍能生成正确类型的候选规则。
3. 在候选规则生成的设备查询中增加 `TenantId` 条件；不匹配时使用通用类型但不读取其他租户数据。
4. 运行根因分析聚焦测试、全量单元测试、Release 构建并进行独立审查后提交。

## 验收标准

- 跨租户设备类型不能写入当前租户候选规则。
- 合法后台事件仍能生成正确设备类型的候选规则。
- 全量单元测试、Release 构建和独立审查通过。

## 验证记录

- 红测（旧实现）：跨租户事件会把其他租户的设备类型写入候选规则。
- 根因分析处理器测试：13/13 通过。
- 全量单元测试：1571/1571 通过。
- Release 构建：0 警告、0 错误。
