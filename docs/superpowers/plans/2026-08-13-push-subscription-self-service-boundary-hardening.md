# 推送订阅自助身份边界加固实施计划

## 目标

在已有租户隔离基础上，确保推送订阅注册和注销只能操作当前认证用户与当前租户，避免应用层参数被错误复用时产生越权写入或删除。

## 实施步骤

1. 添加同租户跨用户注册、注销以及跨租户注册红测，验证旧实现缺少身份绑定。
2. 在自助注册/注销入口增加当前租户和当前用户严格校验；后台按显式目标发送通知的接口不复用该校验。
3. 更新测试上下文，覆盖身份匹配的正向路径以及身份缺失/不匹配时不产生数据库副作用。
4. 运行推送相关测试、全量单元测试、Release 构建并进行独立审查后提交。

## 验收标准

- 当前用户不能替同租户其他用户注册或注销推送订阅。
- 自助订阅不能通过参数写入其他租户，身份为空时也必须拒绝。
- 当前用户和当前租户匹配时，注册、注销功能保持可用。
- 后台向指定用户或租户发送推送的能力不受影响。
- 全量单元测试、Release 构建和独立审查通过。

## 验证记录

- 旧实现红测：同租户跨用户注册、同租户跨用户注销、跨租户注册共 3 项失败，确认测试能捕获越权行为。
- 修复后推送订阅测试：17/17 通过，覆盖空用户身份和后台显式租户广播。
- 全量单元测试：1589/1589 通过（Debug、Release）。
- 集成测试：177 通过、6 跳过（RabbitMQ 专项需设置 RUN_RABBITMQ_INTEGRATION_TESTS=true）。
- Release 解决方案构建：0 警告、0 错误。
- 独立代码审查：Approved，无阻断性问题。
